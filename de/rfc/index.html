Prozess

Was qualifiziert sich als RFC?

Nicht jede Änderung braucht einen RFC — nur wesentliche. Die folgende Tabelle hilft bei der Entscheidung.

Änderungstyp RFC erforderlich? Prozess
Neue Säule oder Entfernung einer Säule Ja RFC → TSC-Abstimmung → PR
Änderungen am Scoring-Modell (PASS-Tiers, Gewichtungen) Ja RFC → TSC-Abstimmung → PR
Breaking Changes am Controls-Schema oder IDs Ja RFC → TSC-Abstimmung → PR
Neuer Working-Group-Vorschlag Ja RFC → Lazy Consensus → Charter veröffentlicht
Governance- oder Rollenänderungen Ja RFC → TSC-Supermehrheit
Neuer Control (nicht-breaking, additiv) Empfohlen PR mit Diskussionslink · Lazy Consensus
Docs-Wording, Tippfehler, Übersetzungen Nein PR only
Website-Inhalte, Blog-Posts Nein PR only
Lifecycle

RFC-Status-Flow

Jeder RFC durchläuft denselben dokumentierten Pfad — vom ersten Entwurf bis zur geschlossenen Entscheidung.

draft
Autor verfasst den Vorschlag in GitHub Discussions
→
open
Mindestens 5 Werktage offen für Community-Kommentare
→
accepted
TSC-Abstimmung oder Lazy Consensus — öffentlich dokumentiert
→
implemented
PR gemergt, Changelog-Eintrag hinzugefügt, RFC geschlossen
Alternative Ergebnisse: rejected (nicht akzeptiert nach Review)  ·  withdrawn (vom Autor zurückgezogen). Beide werden mit Begründung dokumentiert.
Einen RFC schreiben

Wie man einen guten RFC schreibt

Drei Dinge, die den Unterschied zwischen einem RFC, der schnell vorankommt, und einem, der steckenbleibt, ausmachen.

Beschreibe das Problem, nicht die Lösung

Beginne damit, was kaputt oder fehlend ist — nicht mit dem, was du bauen willst. Reviewer müssen dem Problem zustimmen, bevor sie die Lösung bewerten können. Zuerst das „Warum", dann das „Was".

Zeige Trade-offs und Alternativen

Ein starker RFC erklärt, was sonst noch in Betracht gezogen wurde und warum es verworfen wurde. Das spart Review-Zyklen und gibt zukünftigen Maintainern Kontext, wenn der ursprüngliche Autor nicht mehr dabei ist.

Sei spezifisch über die Auswirkungen

Wer ist betroffen? Welche Repositories, Dateien oder öffentlichen Verträge ändern sich? Je klarer der Scope, desto schneller kann die Community nützliches Feedback geben und ein Maintainer entscheiden.
