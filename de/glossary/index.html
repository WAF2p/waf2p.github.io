A
Agentic framework

Bezieht sich auf autonome KI-Agenten, die planen, handeln und mit Systemen interagieren, ohne direkte menschliche Anweisung. In Wombat definiert die Säule Agentisch (Säule 8) Controls zur Steuerung dieser Agenten in produktiven Workloads.

Siehe auch: Pillar, Die 8 Säulen

Antora tooling

Der Static-Site-Generator, mit dem die Wombat-Dokumentation aus AsciiDoc-Quellen gebaut wird. Antora übernimmt Komponentenversionierung, Navigation und Veröffentlichung — die Wombat-Doku liegt unter /docs/ und wird aus dem Repository framework gebaut.

Siehe auch: AsciiDoc

AsciiDoc tooling

Die Auszeichnungssprache, in der die Dokumentation des Wombat-Frameworks geschrieben wird. Ähnlich wie Markdown, aber mit reichhaltigerer Semantik für strukturierte Dokumentation. Alle Dateien in modules/ROOT/pages/ verwenden AsciiDoc (Endung.adoc ).

Assessment framework

Eine strukturierte Bewertung eines Cloud-Workloads anhand der Wombat-Controls über alle zutreffenden Säulen. Ergebnis eines Assessments ist eine Menge von Findings pro Control sowie ein PASS-Score pro Säule und insgesamt.

Siehe auch: Workload, PASS model

C
Charter governance

Ein kurzes Dokument, das Zweck, Umfang, Ergebnisse, Leitung und Kommunikationskanal einer Working Group festlegt. Eine Charta ist Voraussetzung für die offizielle Anerkennung einer WG.

Siehe auch: Working Group

Control framework

Eine konkrete, prüfbare Anforderung innerhalb einer Säule. Jeder Control hat eine eindeutige ID, eine Beschreibung, eine Assessment-Frage und eine Begründung. Controls sind die atomare Einheit des Wombat-Frameworks — ein Workload erfüllt einen Control oder eben nicht.

Siehe auch: Control ID, Pillar, Controls library

Control ID framework

Die eindeutige Kennung eines Wombat-Controls nach dem Muster WAF-[PILLAR]-[NUMBER]. Beispiel: WAF-SOV-010 ist der erste Control der Säule Souveränität. Das Säulenkürzel ist ein Code aus drei Buchstaben (z. B. SEC für Security, SOV für Souveränität, AGN für Agentisch). Control-IDs sind stabil — einmal veröffentlicht, werden sie nie geändert oder wiederverwendet.

Controls library framework

Die vollständige Sammlung der Wombat-Controls, gespeichert als strukturierte YAML-Dateien im Repository framework unter modules/controls/. Die Bibliothek umfasst inzwischen 8 Säulen mit über 100 Controls.

Contributor governance

Alle, die einen Pull Request einreichen, ein Issue eröffnen, sich an einer GitHub Discussion beteiligen, einen RFC vorschlagen oder auf andere Weise zu einem Wombat-Repository beitragen. Contributors brauchen keine formalen Berechtigungen — alle GitHub-Nutzer können beitragen.

Siehe auch: Maintainer

D
Dual-licence model governance

Wombat verwendet zwei Lizenzen: Apache License 2.0 für Code, Tooling und Schemas; Creative Commons Attribution 4.0 (CC BY 4.0) für Dokumentation und schriftliche Inhalte. Das ermöglicht breite Wiederverwendung bei gesicherter Namensnennung. Details auf der Seite Rechtliches .

F
Finding framework

Das Ergebnis der Bewertung eines Controls für einen Workload. Ein Finding ist entweder erfüllt, nicht erfülltoder nicht anwendbar. Findings sind die Rohdaten eines Assessments und werden anschließend zu einem PASS-Score aggregiert.

Foundation-ready governance

Ein Qualitätsstandard für das Governance-Modell von Wombat: Struktur, Richtlinien und Transparenz des Projekts erfüllen die Anforderungen für eine Übergabe an eine Open-Source-Foundation (z. B. CNCF, Apache Software Foundation). Foundation-Readiness ist ein erklärtes Ziel der Wombat-Releases v1.x.

G
Governance governance

Die Regeln, Prozesse und Rollen, die festlegen, wie im Wombat-Projekt Entscheidungen getroffen werden. Die Governance von Wombat ist öffentlich dokumentiert und umfasst: RFC-Prozess, Zusammensetzung und Abstimmungen des TSC, Amtszeiten der Maintainer, Regeln für Working Groups und die Durchsetzung des Verhaltenskodex.

Siehe auch: TSC, RFC, Seite Governance & Community

I
IaC — Infrastructure as Code framework

Die Praxis, Cloud-Infrastruktur über maschinenlesbare Konfigurationsdateien statt manueller Prozesse zu verwalten und bereitzustellen. Relevant für mehrere Wombat-Säulen, insbesondere Operational Excellence und Security.

L
Lazy consensus prozess

Ein schlanker Entscheidungsmechanismus für nicht brechende oder risikoärmere Änderungen. Ein Vorschlag wird öffentlich gestellt, mit einem Review-Fenster von mindestens 5 Werktagen. Wird kein begründeter Einwand erhoben, gilt der Vorschlag als angenommen. Bei größeren Änderungen stimmt stattdessen das TSC ab.

Siehe auch: TSC, RFC

M
Maintainer governance

Ein Contributor mit Merge-Rechten auf einem oder mehreren Wombat-Repositories. Maintainer prüfen PRs, nehmen RFCs an oder lehnen sie ab und verantworten Qualität und Ausrichtung ihres Bereichs. Die Amtszeit beträgt 12 Monate und ist verlängerbar. Nach über 90 Tagen Inaktivität kann der Status auf Emeritus gesetzt werden.

Siehe auch: Seite Rollen & Mitglieder

P
PASS model scoring

Das Scoring-Modell von Wombat. PASS steht für die vier Leistungsstufen: Pioneer, Advanced, Solid, Starter. Jede Stufe entspricht einem Grad der Control-Erfüllung innerhalb einer Säule. Das PASS-Modell ist die normative Scoring-Spezifikation — Details auf der WOMBATpass-Seite .

Siehe auch: PASS score, Scoring tier

PASS score scoring

Das Ergebnis der Anwendung des PASS-Modells auf ein Assessment. Ein Workload erhält einen Score pro Säule und einen aggregierten Gesamtscore. Scores werden als Stufen (Pioneer / Advanced / Solid / Starter) statt als Prozentwerte angegeben, um qualitative Reife statt reiner Erfüllungsquoten abzubilden.

Siehe auch: PASS model

Pillar framework

Eine der acht Bewertungsdimensionen von Wombat. Jede Säule bündelt Controls zu einem bestimmten Qualitätsaspekt von Cloud-Workloads. Die acht Säulen sind: Security, Reliability, Performance Efficiency, Cost Optimisation, Operational Excellence, Sustainability, Sovereign und Agentic.

Siehe auch: Control, Die 8 Säulen

Pillar score scoring

Die PASS-Stufe, die eine einzelne Säule erreicht, abgeleitet aus der Erfüllungsquote der Controls und etwaigen Pflicht-Controls dieser Säule. Säulen-Scores werden zum PASS-Gesamtscore aggregiert.

R
RFC — Request for Comments prozess

Ein öffentlicher Vorschlag für eine wesentliche Änderung an Framework, Governance, Tooling oder Scoring-Modell von Wombat. RFCs werden als GitHub Discussions eröffnet, mindestens 5 Werktage lang von der Community geprüft und dann per TSC-Abstimmung oder Lazy Consensus entschieden. Jeder RFC erhält eine fortlaufende ID (RFC-NNNN) und wird im RFC-Tracker.

Siehe auch: RFC lifecycle, Lazy consensus

RFC lifecycle prozess

Die definierten Zustände, die ein RFC durchläuft: draft (in Arbeit) → open (offen für Community-Review) → accepted (Entscheidung gefallen: umsetzen) → implemented (ausgeliefert und geschlossen). Alternative Ausgänge: rejected oder withdrawn. Alle Zustände und Übergänge sind öffentlich dokumentiert.

S
Scoring tier scoring

Eine der vier Stufen im PASS-Modell. In absteigender Reihenfolge: Pioneer (höchste), Advanced, Solid, Starter (Basis). Die Stufen spiegeln Breite und Tiefe der Control-Erfüllung wider, nicht nur die Anzahl bestandener Controls.

Siehe auch: PASS model

Sovereign pillar framework

Die 7. Säule von Wombat für Datensouveränität, regulatorische Compliance und rechtliche Kontrolle über Zuständigkeiten. Eingeführt mit 10 initialen Controls (WAF-SOV-010 bis WAF-SOV-100). Besonders relevant für regulierte Branchen und Workloads in der EU.

T
TSC — Technical Steering Committee governance

Das leitende Gremium des Wombat-Projekts. Das TSC verantwortet die technische Ausrichtung, RFC-Entscheidungen und die Ernennung von Maintainern. Mitglieder amtieren für verlängerbare 12-monatige Amtszeiten. Die Zusammensetzung folgt dem Prinzip „aktive Contributors zuerst“ und einer anbieterneutralen Balance. Alle TSC-Entscheidungen sind öffentlich dokumentiert.

Siehe auch: Governance & Community, Rollen & Mitglieder

V
Vendor-neutral framework

Ein zentrales Designprinzip von Wombat: Säulen, Controls und Scoring-Modell gelten gleichermaßen für Workloads bei jedem Cloud-Anbieter (AWS, Azure, GCP und weitere). Kein Control ist anbieterspezifisch, sofern er nicht ausdrücklich so gekennzeichnet ist. Das ermöglicht konsistente anbieterübergreifende Assessments und verhindert einen Lock-in in die Review-Methodik eines einzelnen Anbieters.

W
Wombat framework

Cloud Governance & IaC Validation. Ein quelloffenes, anbieterneutrales Framework zur Bewertung und Verbesserung der Qualität von Cloud-Workloads. Wombat erweitert klassische Well-Architected-Reviews um ein transparentes, Community-getriebenes Scoring-Modell (PASS) und eine maschinenlesbare Controls-Bibliothek über 8 Säulen und mehr als 100 Controls.

WOMBATpass tooling

Die offizielle Assessment-Tooling-Suite von Wombat: CLI, Server, Dashboard und Web-Scorecard. WOMBATpass nutzt die Controls-Bibliothek, bewertet einen Workload und erzeugt einen PASS-Score-Report. Aktuelles Release: v1.1.0.

Working Group (WG) governance

Ein themenbezogenes Contributor-Team innerhalb von Wombat. Working Groups entwickeln bestimmte Teile des Frameworks — eine Säule, eine Tooling-Komponente, eine Referenzarchitektur — und liefern Ergebnisse als PRs und RFCs. Alle Contributors können eine WG mit Charta, Leitung und einem Maintainer als Paten vorschlagen.

Siehe auch: Charter, Mitwirken

Workload framework

Die Cloud-Anwendung, der Service oder das System, das mit Wombat bewertet wird. Ein Workload hat einen definierten Umfang (z. B. ein Microservice, eine Datenplattform, ein ganzes Produkt) und wird anhand der zutreffenden Wombat-Controls bewertet. Der Umfang wird vor Beginn eines Assessments festgelegt.

Siehe auch: Assessment
