Eine sichere Bridge, kein zweites Auth-System.

Die Bridge nutzt Identität, Berechtigungen und Audit-Trails von WAFPass. Sie validiert, leitet weiter und filtert — und speichert niemals Cloud-Secrets oder IdP-Passwörter.

IdP-agnostisch

Keine direkte Integration von Keycloak, Entra oder Okta. Die Bridge vertraut Tokens, die ausgestellt werden von wafpass-server, das OIDC- und SAML-Flows bereits übernimmt.

Token-Introspection

Jede neue SSE-Verbindung wird geprüft gegen GET /auth/me. Sofortige Erkennung von Widerrufen, kein Teilen von JWT-Secrets nötig.

Tools nach Least Privilege

tools/list wird nach der Rolle des angemeldeten Nutzers gefiltert. Endpunkte nur für Admins bleiben für Engineers unsichtbar, und zeilenbasierte Autorisierung gilt bei jedem Backend-Aufruf.

Kontextweitergabe

Der ursprüngliche Authorization: Bearer Header wird bei jeder weitergeleiteten Anfrage an WAFPass übergeben, sodass Nutzeridentität und Audit-Zuordnung erhalten bleiben.

Aus OpenAPI generiert

Beim Start ruft die Bridge /openapi.json ab und registriert sichere Operationen als typisierte MCP-Tools mit Pydantic-validierten Argumenten.

stdio oder SSE

Betreiben Sie die Bridge als lokalen stdio-Prozess für Claude Desktop oder stellen Sie sie per HTTP/SSE für entfernte MCP-Hosts und browserbasierte Clients bereit.

Claude Desktop in Minuten verbinden.

Installieren Sie die Bridge, melden Sie sich einmal an und verweisen Sie Claude Desktop auf den stdio-Befehl. Keine Zertifikate, keine offenen Ports, keine zusätzliche Authentifizierung.

1. Installieren und konfigurieren 
git clone https://github.com/WAF2p/wafpass-mcp.git
cd wafpass-mcp
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"

wafpass-mcp-configure
# Enter WAFpass API URL, username and password
2. Claude-Desktop-Konfiguration (stdio) 
{
  "mcpServers": {
    "wafpass": {
      "command": "/path/to/wafpass-mcp/.venv/bin/wafpass-mcp-stdio"
    }
  }
}
3. Docker Compose (Alternative) 
# From the WAF++ repository root
docker compose up -d wafpass-mcp
docker compose logs -f wafpass-mcp

# SSE endpoint: http://localhost:3001/sse
# Override WAFPASS_TOKEN_MODE or WAFPASS_JWT_SECRET in .env

So fügt sich die Bridge ein.

Der Nutzer authentifiziert sich über den vorgelagerten IdP, tauscht Tokens mit WAFPass und bringt dasselbe Bearer-Token zum MCP-Host. Die Bridge leitet Anfragen weiter und filtert Tools nach Rolle.
