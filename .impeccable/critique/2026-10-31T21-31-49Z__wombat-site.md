# Wombat site critique & technical audit

Method: dual-agent (A: design review · B: detector + browser evidence) plus an independent technical audit (C)
Target slug: wombat-site
Date: 2026-10-31
Scope: 14 English routes and the shared layouts/includes/SCSS, built from feat/rebrand_main and served at localhost:8000.

## Verdict

The rebrand has a real voice (mascot, "Context, not competition", RFC tracker, controls vocabulary) sitting on a stock dev-tool composition, and it ships with three blocking defects that hide or break primary content. Design Health 21/40; Technical Audit 7/20 (Poor). Fix the P0s before merge.

## Design specificity

Template, partly authored. The voice is Wombat's; the composition is a stock dev-tool landing system. The same hero grid (h1 + lead + two pills + right screenshot) repeats across Home, Controls, Pillars, Glossary, Comparison, RFC, Changelog, Roles, Conferences and WOMBATpass with only copy swapped, followed by the standard manifesto, 3-up benefits, 4-up features, stat band and alternating screenshot rows.

Implementation Integrity: FAIL. Three visual systems ship at once: `theme/_base` tokens, `home-v6` `--wf6-*` tokens scoped to `.frontpage`/`.pil-page`, and a 55 KB docs stylesheet with 50+ hex values. Token scope bugs silently blank CTAs. Dead artifacts from prior iterations ship (`nav-hover-intent.js` targets selectors that no longer exist). Inline `onclick` contradicts the repo's own AGENTS.md.

## P0 — blocking

1. **Docs dead-end (240 links, 96 pages).** Every marketing page links to `/docs/wafpp/1.1.0-en/…`, but CI builds `antora-playbook.yml` from `main-en`/`main-de`, which declare version `1.0.2-en`/`1.0.2-de`. The built site serves only 1.0.2. `scripts/check-links.mjs` cannot catch it: `SKIP_PREFIXES = ['/docs/']`. Verified: 240 hrefs, 96 pages, 18 distinct doc paths, all 404. Fix: align the docs version (merge the framework branch or pin the links) and make the link check cover `/docs` when docs are built.
2. **`/wombatpass/` closing CTA is blank.** `.wfp-cta-section` uses `background: var(--wf6-ink)` (`_sass/wombatpass.scss:240`), but `--wf6-ink` is defined only under `.frontpage, .pil-page` (`_sass/home-v6.scss:18,49`). The body has no such class, so the background is transparent while heading/lead/buttons are forced white (`wombatpass.scss:249-275`). Computed: body `rgb(255,255,255)`, section transparent, heading white. Screenshot: white slab. Same pattern in `wombatpass-install.scss:356`, `changelog-v2.scss:206`, `use-cases-v2.scss:196`, `cto-v2.scss:187`, `about-v2.scss:235`, `rfc-v2.scss:78`, `glossary.scss:209`.
3. **Dark-band "line" buttons invisible.** `.wf6-btn--line { color: var(--wf6-text) }` (`_sass/home-v6.scss:141-145`) with no `.wf6-section--dark` override. Computed on `/controls/` and `/saeulen/`: text `rgb(11,18,32)` on `rgb(10,14,26)`, ≈1.03:1. "Read the docs" and "Join the community" are effectively unreadable. WCAG 1.4.3.

## P1 — major

4. Accent contrast: white on `#0094FF` = 3.14:1 (`_design-language.scss:73`, `home-v6.scss:130`, `_cookie-consent.scss:286-288`, docs links).
5. No-JS: `.dl-rise`/`.wf6-rise` are `opacity:0` with no fallback (`_design-language.scss:243-247`); measured 26/26 hidden on home, including the post `h1`.
6. Cookie dialog: `aria-modal="true"` but no focus trap (`assets/js/main.js:298-311`); actions below the fold at 900px and on mobile.
7. Mobile nav: no Escape close, no trap, background still tabbable (`main.js:1-19`, `_layout.scss:257-276`).
8. English docs carry German accessible names: `Menü öffnen`, `Hauptnavigation`, `Theme umschalten` (`supplemental-ui/partials/header-content.hbs:8,12,85`) on `lang="en"`.
9. Image payload: both light+dark 4336×2672 PNGs load eagerly (3.2 MB) for a 484 px slot (`index.html:37-44`), ~11.6 MB total on home, no `srcset`/WebP.
10. Docs nav and language switch are JS-only `href="#"`: 12 dead links (`header-content.hbs:16-53,72-73`).

## Detector evidence

136 findings across 14 pages: 108 warnings, 28 advisory, 0 errors. Rules: line-length 49, dark-glow 30, straggler 25, low-contrast 15, overused-font 13, em-dash-overuse 2, kicker-above-heading 1, unbalanced-heading 1.

False positives removed: 26/30 `dark-glow` are the brand header CTAs (offset shadows, light page), and `overused-font` is the declared brand font Plus Jakarta Sans (`_sass/theme/_base.scss:98`). Real: line length 91-150 chars in glossary/changelog/blog; cookie "Accept all" contrast; stragglers; unbalanced heading in `#signals h2.dl-heading`.

## What's working

- Editorial type and glossary anatomy: League Spartan / Plus Jakarta with a 5-size clamp scale; term + category + definition + "See also" is the strongest Read pattern on the site.
- RFC tracker: real records with status, author, dates, links, two filter dimensions, and a genuinely helpful empty state.
- Interaction care: download button states, lightbox focus restore, persisted theme, `prefers-reduced-motion` handling, native labeled cookie checkboxes.
- Both project checks pass: 0 broken internal links outside `/docs`, 0 HTML validation errors.
- No horizontal overflow at 320/390 px on all 14 pages; single `h1` and proper landmarks.

## Persona red flags

- Public-sector compliance lead (BSI C5 / ISO 27001): framework names are plain spans, control IDs carry no descriptions, "Explore" 404s, jurisdiction counts disagree. Cannot produce evidence from this site.
- Cloud architect benchmarking AWS WA / Azure CAF: `/comparison/` promises "Context, not competition" but the table sits below the fold behind a generic screenshot; "0% vendor lock-in" reads as marketing.
- OSS contributor / security engineer: `/rfc/` is excellent, but "Built by four people", "1 currently staffed", unexplained ranks, and old-branded docs make a standards project look like a side project.

## Minor observations

- Header/content left edges misalign (logo x≈96 vs H1 x=64 at 1280).
- Focus rings are default `auto 1px` and near-invisible on the blue Documentation button.
- Stat bands pad with non-metrics: "Linked / Public / RSS", "Open", "14 Letters".
- Footer has no group headings and one 14-link column; blog meta wraps with a dangling separator on mobile.
- 5-up role cards hold 6-7 lines each; the pillar grid leaves a 2-column hole before Sovereign/Agentic.

## Questions to consider

1. Is 1.1.0 real and deployed, or is 1.0.2 the release? Which number should every page state?
2. Who is the primary home visitor: the compliance lead inspecting controls, or the engineer installing a CLI?
3. Should control IDs stay `WAF-*` after the rename, and where is that explained?
4. Should the mascot carry trust surfaces, or should proof be visually quieter than the cartoon?
