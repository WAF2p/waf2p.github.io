Aan de slag.

Vier stappen van nieuwkomer tot contributor.

  1. Verken de GitHub-organisatie

    Bekijk open issues met het label good first issue of help wanted op github.com/{{ site.data.github.org }}. Nog geen issue? Open er een en beschrijf wat je wilt oppakken.

  2. Stel je voor op Slack

    Word lid van de community op Slack, zeg hallo in #general, stel vragen en ontdek welke werkgroep past bij je achtergrond en interesses.

  3. Fork → branch → PR

    Fork de juiste repository, maak een featurebranch en open een pull request. Een maintainer reviewt hem, geeft feedback en begeleidt je door het proces.

  4. Grotere wijzigingen? Open eerst een RFC

    Voor nieuwe pijlers, breaking changes, scoringwijzigingen of governance-updates — schrijf een RFC in GitHub Discussions. De community beoordeelt hem voordat de implementatie begint. Zo blijven beslissingen herleidbaar.

Werkgroepen.

Werkgroepen zijn thematische teams die specifieke onderdelen van Wombat bouwen. Iedereen kan er een voorstellen — je hebt alleen een charter, minstens één lead en een maintainer als sponsor nodig.

Vind een werkgroep

Bekijk open werkgroepvoorstellen in GitHub Discussions en word lid van het bijbehorende Slack-kanaal. Je kunt bijdragen zonder voltijdse verplichting.

Start een werkgroep

Schrijf een charter in een GitHub-discussie, zoek een maintainer als sponsor en kondig het aan op Slack. Een werkgroep kan elke reikwijdte hebben: één pijler, een toolingvraag, een scoringaanpak.

Lever resultaten

Resultaten van werkgroepen komen terug als PR's en RFC's. Elk resultaat is openbaar, herleidbaar en citeerbaar — in lijn met de transparantieprincipes van Wombat.

Levenscyclus van features.

Elke Wombat-capaciteit doorloopt een duidelijke levenscyclus. Elke fase hangt af van het RFC-/ADR-proces, zodat gebruikers altijd weten hoe volwassen een feature is en wat ze kunnen verwachten voordat ze die gaan gebruiken.

Closed Alpha

Privé verkennen

Een kleine groep early adopters test de capaciteit in gecontroleerde omgevingen. De API, het scoringmodel of de CLI-interface zijn bewust instabiel en kunnen zonder aankondiging veranderen.

Zo kom je hier
  • Een concept- of open RFC definieert het experiment
  • Early-accessgroep alleen op uitnodiging
  • Feedback zorgt voor snelle iteraties

Alpha

Openbaar testen

De capaciteit is beschikbaar voor iedereen die haar wil proberen. Interfaces zijn grotendeels stabiel, maar breaking changes op basis van communityfeedback zijn nog mogelijk.

Zo kom je hier
  • RFC geaccepteerd met alfascope
  • Openbare documentatie en release notes beschikbaar
  • GitHub Discussions verzamelt feedback
Doe mee aan alfadiscussies →
Beta

In productie gebruiken

De capaciteit is functioneel compleet en productieklaar voor de gedocumenteerde use cases. Kleine aanpassingen zijn nog mogelijk, maar breaking changes vereisen expliciete migratierichtlijnen.

Zo kom je hier
  • RFC geaccepteerd en implementatie gemerged
  • Een ADR legt de criteria voor productierijpheid vast
  • Review op beveiliging, performance en compatibiliteit doorstaan
Geaccepteerde RFC's volgen →
GA

Algemene beschikbaarheid

De capaciteit wordt volledig ondersteund, valt onder het stabiliteitsbeleid en wordt voor alle gebruikers aanbevolen. Ze wordt onderhouden met achterwaarts compatibele updates en duidelijke deprecatietermijnen.

Zo kom je hier
  • De RFC-status verandert naar implemented
  • Een definitieve ADR bekrachtigt het stabiele contract
  • Opgenomen in de officiële releasetrein
Geïmplementeerde RFC's bekijken →

Elke fase is gekoppeld aan het RFC-/ADR-proces. Wanneer een RFC wordt geaccepteerd, start de alfa- of bètafase; wanneer hij wordt gemarkeerd als implemented , is de capaciteit klaar voor GA. Bekijk het volledige beeld in de RFC-tracker of stel de volgende wijziging voor in GitHub Discussions.

Het RFC-proces.

Belangrijke wijzigingen lopen via een RFC (Request for Comments). Het proces is licht, maar zorgt ervoor dat elke beslissing door de community wordt gereviewd en gedocumenteerd.
