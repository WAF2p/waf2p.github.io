Proces

Wat is een RFC?

Niet elke verandering heeft een RFC nodig, alleen belangrijke. Gebruik de onderstaande tabel om te beslissen.

Type wijzigen RFC nodig? Proces
Nieuwe pijler of verwijdering van een pijler Ja. RFC → TSC vote → PR
Scoremodelwijzigingen (PASS-niveaus, gewichten) Ja. RFC → TSC vote → PR
Breaking change to control schema or IDs Ja. RFC → TSC vote → PR
Voorstel van de nieuwe werkgroep Ja. RFC &rr; luie consensus &rr; charter gepubliceerd
Bestuur of rolveranderingen Ja. RFC → TSC supermeerderheid
Nieuwe controle (niet breken, additief) Aanbevolen PR met discussielink · luie consensus
Documenten tekst, typo fixes, vertalingen Nee Uitsluitend PR
Website-inhoud, blogberichten Nee Uitsluitend PR

RFC-statusstroom

Elke RFC volgt hetzelfde gedocumenteerde pad van het eerste ontwerp naar het gesloten besluit.

ontwerp
Auteur schrijft het voorstel in GitHub discussies
→
open
Minimum 5 werkdagen open voor community commentaar
→
aanvaard
TSC-stem of luie consensus openbaar gedocumenteerd
→
geïmplementeerd
Samengevoegd PR, veranderinglog toegevoegd, RFC gesloten
Alternatieve resultaten: verworpen(niet geaccepteerd na beoordeling)  ·  ingetrokken(geroepen door auteur). Beide zijn met redenen gedocumenteerd.
Een RFC schrijven

Hoe schrijf je een goede RFC

Drie dingen die het verschil maken tussen een snelle RFC en een die stilstaat.

Zeg het probleem, niet de oplossing.

Begin met wat gebroken is of ontbreekt, niet met wat je wilt bouwen. De beoordelaars moeten het erover eens zijn dat het probleem echt is voordat ze uw voorgestelde oplossing kunnen evalueren. Zet de "waarom" voor de "wat."

Toon trade-offs en alternatieven

Een sterke RFC legt uit wat er nog meer werd overwogen en waarom het werd afgewezen. Dit bespaart beoordelingscycli en geeft toekomstige onderhouders context wanneer de oorspronkelijke auteur verder is gegaan.

Wees specifiek over impact

Wie is er getroffen? Welke repositories, bestanden of overheidsopdrachten veranderen? Hoe duidelijker de reikwijdte, hoe sneller de gemeenschap nuttige feedback kan geven en een onderhouder een beslissing kan nemen.
