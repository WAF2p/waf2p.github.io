Compliance in je pipeline.

Eén stap. Volledig inzicht.

De action regelt de installatie van de CLI, het scannen, het uploaden van resultaten en het afdwingen van policies, zodat je team zich op opleveren kan richten.

CLI automatisch installeren

Installeert automatisch de nieuwste wafpass-core vanaf PyPI, of gebruik een eigen pip-bron of een vooraf geïnstalleerde binary.

Multi-IaC-scan

Scan Terraform-, Bicep-, CDK- of Pulumi-bestanden in één stap. Ondersteunt meerdere paden en Terraform-plan-JSON voor een overzicht van wijzigingen.

Naar de server sturen

Uploadt de volledige wafpass-result.json naar POST /api/v1/runs , zodat dashboards en bewijspakketten actueel blijven.

Policy-gates

Configureerbare fail_on -policies, van never tot critical. De stap faalt pas nadat het resultaat veilig op de server is opgeslagen.

Flexibele authenticatie

Gebruik een Bearer-token voor interactieve gebruikers of een ingest-API-sleutel voor headless CI/CD-runs. Beide worden veilig naar de server doorgegeven.

CI/CD-metadata

Markeert runs als is_cicd: true met triggered_by: github-actions en geeft branch, commit-SHA, project en stage automatisch door.

Voeg hem toe aan elke workflow.

Check je repo uit, draai de action en toon complianceresultaten waar je team al werkt.

.github/workflows/wafpass.yml
{% raw %}
name: WAF++ PASS Scan

on:
  push:
    branches: [main, develop]
  pull_request:

jobs:
  wafpass:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Run WAF++ PASS
        uses: WAF2p/wafpass-action@v0.1.1
        with:
          server_url: ${{ vars.WAFPASS_SERVER_URL }}
          api_key: ${{ secrets.WAFPASS_API_KEY }}
          scan_path: ./infra
          iac_framework: terraform
          project: ${{ github.repository }}
          stage: ${{ github.ref_name == 'main' && 'prod' || 'dev' }}
          fail_on: high
          upload_source: true
{% endraw %}
