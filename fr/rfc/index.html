Qu'est-ce qui justifie une RFC ?

Tous les changements n'exigent pas une RFC, seulement les plus importants. Utilisez le tableau ci-dessous pour décider.

Type de changement RFC nécessaire ? Processus
Nouveau pilier ou suppression d'un pilier Oui RFC → vote du TSC → PR
Changements du modèle de scoring (niveaux PASS, pondérations) Oui RFC → vote du TSC → PR
Changement incompatible du schéma ou des ID des contrôles Oui RFC → vote du TSC → PR
Proposition d'un nouveau groupe de travail Oui RFC → lazy consensus → charte publiée
Changements de gouvernance ou de rôles Oui RFC → majorité qualifiée du TSC
Nouveau contrôle (compatible, additif) Recommandé PR avec lien vers la discussion, lazy consensus
Formulations de la documentation, coquilles, traductions Non PR uniquement
Contenu du site web, articles de blog Non PR uniquement

Cycle de statut d'une RFC.

Chaque RFC suit le même parcours documenté, du premier brouillon à la décision finale.

draft
La personne autrice rédige la proposition dans GitHub Discussions
→
open
Ouverte au moins 5 jours ouvrés aux commentaires de la communauté
→
accepted
Vote du TSC ou lazy consensus, documenté publiquement
→
implemented
PR fusionnée, entrée ajoutée au journal, RFC close
Autres issues possibles : rejected (non acceptée après relecture), withdrawn (retirée par la personne autrice). Les deux sont documentées avec leurs motifs.

Bien rédiger une RFC.

Trois éléments qui font la différence entre une RFC qui avance vite et une RFC qui stagne.

Exposez le problème, pas la solution

Commencez par ce qui est cassé ou manquant, pas par ce que vous voulez construire. Les relecteurs doivent s'accorder sur la réalité du problème avant d'évaluer votre solution. Expliquez le « pourquoi » avant le « quoi ».

Montrez les compromis et les alternatives

Une bonne RFC explique ce qui a été envisagé d'autre et pourquoi cela a été écarté. Cela évite des cycles de relecture et donne du contexte aux futurs mainteneurs lorsque la personne autrice n'est plus là.

Soyez précis sur l'impact

Qui est concerné ? Quels dépôts, fichiers ou contrats publics changent ? Plus le périmètre est clair, plus vite la communauté peut donner un retour utile et un mainteneur trancher.
