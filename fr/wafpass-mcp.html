Une passerelle sécurisée, pas un second système d'authentification.

La passerelle réutilise l'identité, les permissions et les pistes d'audit de WAFPass. Elle valide, relaie et filtre, sans jamais stocker de secrets cloud ni de mots de passe de l'IdP.

Indépendant de l'IdP

Aucune intégration directe avec Keycloak, Entra ou Okta. La passerelle fait confiance aux jetons émis par wafpass-server, qui gère déjà les flux OIDC et SAML.

Introspection des jetons

Chaque nouvelle connexion SSE est validée auprès de GET /auth/me. Révocations détectées instantanément, sans partage de secret JWT.

Outils au moindre privilège

tools/list est filtré selon le rôle de l'utilisateur authentifié. Les endpoints réservés aux administrateurs restent invisibles pour les ingénieurs, et l'autorisation par ligne s'applique à chaque appel au backend.

Propagation du contexte

L'en-tête d'origine Authorization: Bearer est transmis à WAFPass à chaque requête relayée, ce qui préserve l'identité de l'utilisateur et l'attribution dans l'audit.

Généré depuis OpenAPI

Au démarrage, la passerelle récupère /openapi.json et enregistre les opérations sûres comme outils MCP typés, avec des arguments validés par Pydantic.

stdio ou SSE

Exécutez la passerelle comme processus stdio local pour Claude Desktop, ou exposez-la en HTTP/SSE pour des hôtes MCP distants et des clients web.

Connectez Claude Desktop en quelques minutes.

Installez la passerelle, connectez-vous une fois et pointez Claude Desktop vers la commande stdio. Ni certificat, ni port ouvert, ni authentification supplémentaire.

1. Installer et configurer 
git clone https://github.com/WAF2p/wafpass-mcp.git
cd wafpass-mcp
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"

wafpass-mcp-configure
# Enter WAFpass API URL, username and password
2. Configuration de Claude Desktop (stdio) 
{
  "mcpServers": {
    "wafpass": {
      "command": "/path/to/wafpass-mcp/.venv/bin/wafpass-mcp-stdio"
    }
  }
}
3. Docker Compose (alternative) 
# From the WAF++ repository root
docker compose up -d wafpass-mcp
docker compose logs -f wafpass-mcp

# SSE endpoint: http://localhost:3001/sse
# Override WAFPASS_TOKEN_MODE or WAFPASS_JWT_SECRET in .env

Comment la passerelle s'intègre.

L'utilisateur s'authentifie via l'IdP en amont, échange des jetons avec WAFPass, puis apporte le même jeton Bearer à l'hôte MCP. La passerelle relaie les requêtes et filtre les outils selon le rôle.
