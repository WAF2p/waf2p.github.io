A
Agentic framework

Relatif aux agents d'IA autonomes qui planifient, agissent et interagissent avec des systèmes sans instruction humaine directe. Dans Wombat, le pilier Agentique (pilier 8) définit des contrôles pour encadrer ces agents dans les workloads en production.

Voir aussi : Pillar, Les 8 piliers

Antora outillage

Le générateur de site statique utilisé pour construire la documentation Wombat à partir de sources AsciiDoc. Antora gère le versionnage des composants, la navigation et la publication — la documentation Wombat se trouve sous /docs/ et est construite à partir du dépôt framework .

Voir aussi : AsciiDoc

AsciiDoc outillage

Le langage de balisage utilisé pour rédiger la documentation du framework Wombat. Proche de Markdown, mais avec une sémantique plus riche pour la documentation structurée. Tous les fichiers de modules/ROOT/pages/ utilisent AsciiDoc (extension.adoc ).

Assessment framework

Une évaluation structurée d'un workload cloud au regard des contrôles Wombat sur tous les piliers applicables. Elle produit un ensemble de constats par contrôle et un score PASS par pilier et global.

Voir aussi : Workload, PASS model

C
Charter gouvernance

Un court document qui définit l'objectif, le périmètre, les livrables, les responsables et le canal de communication d'un groupe de travail. Une charte est requise pour qu'un GT soit officiellement reconnu.

Voir aussi : Working Group

Control framework

Une exigence précise et vérifiable au sein d'un pilier. Chaque contrôle possède un ID unique, une description, une question d'évaluation et une justification. Les contrôles sont l'unité atomique du framework Wombat : un workload satisfait un contrôle ou non.

Voir aussi : Control ID, Pillar, Controls library

Control ID framework

L'identifiant unique d'un contrôle Wombat, selon le modèle WAF-[PILLAR]-[NUMBER]. Exemple : WAF-SOV-010 est le premier contrôle du pilier Souveraineté. L'abréviation du pilier est un code de trois lettres (p. ex. SEC pour Sécurité, SOV pour Souveraineté, AGN pour Agentique). Les ID de contrôle sont stables : une fois publiés, ils ne changent jamais et ne sont jamais réutilisés.

Controls library framework

L'ensemble des contrôles Wombat, stockés sous forme de fichiers YAML structurés dans le dépôt framework sous modules/controls/. La bibliothèque couvre désormais 8 piliers et plus de 100 contrôles.

Contributor gouvernance

Toute personne qui soumet une pull request, ouvre une issue, participe à une GitHub Discussion, propose une RFC ou contribue d'une autre manière à un dépôt Wombat. Aucune permission formelle n'est nécessaire : tout utilisateur GitHub peut contribuer.

Voir aussi : Maintainer

D
Dual-licence model gouvernance

Wombat utilise deux licences : Apache License 2.0 pour le code, l'outillage et les schémas ; Creative Commons Attribution 4.0 (CC BY 4.0) pour la documentation et les contenus rédigés. Cela permet une large réutilisation tout en garantissant l'attribution. Voir la page Mentions légales pour plus de détails.

F
Finding framework

Le résultat de l'évaluation d'un contrôle sur un workload. Un constat est soit satisfait, non satisfaitou non applicable. Les constats sont la sortie brute d'une évaluation ; ils sont ensuite agrégés en un score PASS.

Foundation-ready gouvernance

Un niveau de qualité du modèle de gouvernance de Wombat indiquant que la structure, les politiques et la transparence du projet satisfont aux exigences d'un don à une fondation open source (p. ex. CNCF, Apache Software Foundation). C'est un objectif affiché des versions v1.x de Wombat.

G
Governance gouvernance

L'ensemble des règles, processus et rôles qui déterminent comment les décisions sont prises dans le projet Wombat. La gouvernance de Wombat est documentée publiquement et couvre : le processus RFC, la composition et les votes du TSC, les mandats des mainteneurs, les règles des groupes de travail et l'application du code de conduite.

Voir aussi : TSC, RFC, Page Gouvernance et communauté

I
IaC — Infrastructure as Code framework

La pratique consistant à gérer et provisionner l'infrastructure cloud au moyen de fichiers de configuration lisibles par machine plutôt que de processus manuels. Elle concerne plusieurs piliers de Wombat, notamment Excellence opérationnelle et Sécurité.

L
Lazy consensus processus

Un mécanisme de décision léger pour les changements non cassants ou à faible risque. Une proposition est publiée avec une fenêtre de relecture d'au moins 5 jours ouvrés. En l'absence d'objection fondée, elle est réputée acceptée. Pour les changements majeurs, c'est le vote du TSC qui s'applique.

Voir aussi : TSC, RFC

M
Maintainer gouvernance

Un contributeur disposant des droits de merge sur un ou plusieurs dépôts Wombat. Les mainteneurs relisent les PR, approuvent ou rejettent les RFC et sont responsables de la qualité et de l'orientation de leur domaine. Le mandat est de 12 mois, renouvelable. Plus de 90 jours d'inactivité peuvent entraîner le statut d'émérite.

Voir aussi : Page Rôles et membres

P
PASS model scoring

Le modèle de scoring de Wombat. PASS désigne les quatre niveaux de réussite : Pioneer, Advanced, Solid, Starter. Chaque niveau correspond à un degré de satisfaction des contrôles au sein d'un pilier. Le modèle PASS est la spécification normative du scoring — voir la page WOMBATpass pour plus de détails.

Voir aussi : PASS score, Scoring tier

PASS score scoring

Le résultat de l'application du modèle PASS à une évaluation. Un workload reçoit un score par pilier et un score global agrégé. Les scores sont exprimés en niveaux (Pioneer / Advanced / Solid / Starter) et non en pourcentages, pour refléter la maturité qualitative plutôt que de simples taux de réussite.

Voir aussi : PASS model

Pillar framework

L'une des huit dimensions d'évaluation de Wombat. Chaque pilier regroupe des contrôles portant sur un aspect précis de la qualité des workloads cloud. Les huit piliers sont : Security, Reliability, Performance Efficiency, Cost Optimisation, Operational Excellence, Sustainability, Sovereign et Agentic.

Voir aussi : Control, Les 8 piliers

Pillar score scoring

Le niveau PASS atteint pour un pilier donné, déduit du taux de satisfaction des contrôles et des éventuels contrôles obligatoires de ce pilier. Les scores par pilier sont agrégés dans le score PASS global.

R
RFC — Request for Comments processus

Une proposition publique de changement important du framework, de la gouvernance, de l'outillage ou du modèle de scoring de Wombat. Les RFC sont ouvertes sous forme de GitHub Discussions, relues par la communauté pendant au moins 5 jours ouvrés, puis tranchées par un vote du TSC ou par lazy consensus. Chaque RFC reçoit un ID séquentiel (RFC-NNNN) et est suivie dans le suivi des RFC.

Voir aussi : RFC lifecycle, Lazy consensus

RFC lifecycle processus

Les états définis par lesquels passe une RFC : draft (en rédaction) → open (ouverte à la relecture communautaire) → accepted (décision prise : on avance) → implemented (livrée et close). Issues alternatives : rejected ou withdrawn. Tous les états et transitions sont documentés publiquement.

S
Scoring tier scoring

L'un des quatre niveaux du modèle PASS. Par ordre décroissant : Pioneer (le plus élevé), Advanced, Solid, Starter (socle). Les niveaux reflètent l'étendue et la profondeur de la satisfaction des contrôles, pas seulement le nombre de contrôles réussis.

Voir aussi : PASS model

Sovereign pillar framework

Le 7e pilier de Wombat, qui couvre la souveraineté des données, la conformité réglementaire et le contrôle juridictionnel. Introduit avec 10 contrôles initiaux (WAF-SOV-010 à WAF-SOV-100). Particulièrement pertinent pour les secteurs réglementés et les workloads basés dans l'UE.

T
TSC — Technical Steering Committee gouvernance

L'organe directeur du projet Wombat. Le TSC est responsable de l'orientation technique, des décisions sur les RFC et de la nomination des mainteneurs. Ses membres ont des mandats renouvelables de 12 mois. La composition suit le principe « contributeurs actifs d'abord » et un équilibre neutre entre fournisseurs. Toutes les décisions du TSC sont documentées publiquement.

Voir aussi : Gouvernance et communauté, Rôles et membres

V
Vendor-neutral framework

Un principe de conception central de Wombat : les piliers, les contrôles et le modèle de scoring s'appliquent de la même façon aux workloads de n'importe quel fournisseur cloud (AWS, Azure, GCP et autres). Aucun contrôle n'est propre à un fournisseur, sauf mention explicite. Cela permet des évaluations cohérentes entre fournisseurs et évite l'enfermement dans la méthode de revue d'un seul.

W
Wombat framework

Cloud Governance & IaC Validation. Un framework open source et neutre vis-à-vis des fournisseurs pour évaluer et améliorer la qualité des workloads cloud. Wombat enrichit les revues well-architected classiques d'un modèle de scoring transparent et communautaire (PASS) et d'une bibliothèque de contrôles lisible par machine couvrant 8 piliers et plus de 100 contrôles.

WOMBATpass outillage

La suite officielle d'outils d'évaluation de Wombat : CLI, serveur, tableau de bord et scorecard web. WOMBATpass exploite la bibliothèque de contrôles, évalue un workload et produit un rapport de score PASS. Version actuelle : v1.1.0.

Working Group (WG) gouvernance

Une équipe de contributeurs centrée sur un sujet au sein de Wombat. Les groupes de travail construisent des parties précises du framework — un pilier, un composant d'outillage, une architecture de référence — et livrent sous forme de PR et de RFC. Tout contributeur peut proposer un GT avec une charte, un responsable et un mainteneur parrain.

Voir aussi : Charter, Contribuer

Workload framework

L'application, le service ou le système cloud évalué avec Wombat. Un workload a un périmètre défini (p. ex. un microservice, une plateforme de données, un produit entier) et est évalué au regard des contrôles Wombat applicables. Le périmètre est fixé avant le début de l'évaluation.

Voir aussi : Assessment
