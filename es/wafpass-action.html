Un paso. Visibilidad total.

La action se encarga de instalar la CLI, escanear, subir el resultado y aplicar las políticas, para que tu equipo pueda centrarse en entregar.

Instalación automática de la CLI

Instala automáticamente la última versión de wafpass-core desde PyPI, o usa una fuente pip propia o un binario preinstalado.

Escaneo multi-IaC

Escanea archivos de Terraform, Bicep, CDK o Pulumi en un solo paso. Admite varias rutas y el JSON del plan de Terraform para ver los cambios.

Envío al servidor

Sube el wafpass-result.json completo a POST /api/v1/runs para que los paneles y los paquetes de evidencias estén siempre al día.

Puertas de políticas

Políticas fail_on configurables, desde never hasta critical. El paso falla solo después de que el resultado se haya guardado de forma segura en el servidor.

Autenticación flexible

Usa un token Bearer para usuarios interactivos o una clave de API de ingesta para ejecuciones de CI/CD sin interfaz. Ambos se envían de forma segura al servidor.

Metadatos de CI/CD

Marca las ejecuciones como is_cicd: true con triggered_by: github-actions y pasa automáticamente la rama, el SHA del commit, el proyecto y la etapa.

Añádela a cualquier workflow.

Haz checkout del repo, ejecuta la action y muestra los resultados de cumplimiento donde tu equipo ya trabaja.

.github/workflows/wafpass.yml
{% raw %}
name: WOMBATpass Scan

on:
  push:
    branches: [main, develop]
  pull_request:

jobs:
  wafpass:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Run WOMBATpass
        uses: WAF2p/wafpass-action@v0.1.1
        with:
          server_url: ${{ vars.WAFPASS_SERVER_URL }}
          api_key: ${{ secrets.WAFPASS_API_KEY }}
          scan_path: ./infra
          iac_framework: terraform
          project: ${{ github.repository }}
          stage: ${{ github.ref_name == 'main' && 'prod' || 'dev' }}
          fail_on: high
          upload_source: true
{% endraw %}
