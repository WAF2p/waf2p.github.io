Formas de contribuir.

Código, contenido, comunidad: elige lo que encaje con tus habilidades y tu tiempo.

PR e issues

Corrige bugs, implementa controles, mejora las herramientas. Cada PR lo revisa un maintainer y se vincula a una decisión.

Documentación y patrones

Escribe documentación de los pilares, arquitecturas de referencia, patrones de buenas prácticas o ejemplos concretos de proyectos reales.

Revisión de RFC

Comenta RFC abiertas, propón alternativas o vota decisiones del framework. Cada voz cuenta, sobre todo la experiencia práctica.

Localización

Ayuda a traducir el contenido al alemán, al inglés o a otros idiomas. WAF++ debe ser accesible para la comunidad cloud global.

Grupos de trabajo

Únete o propón un grupo de trabajo sobre un pilar concreto, el modelo de puntuación, la biblioteca de controles o una arquitectura de referencia.

Charlas y BoF

Presenta WAF++ en una conferencia, organiza una sesión Birds-of-a-Feather o dirige un taller de la comunidad. La experiencia práctica vale oro.

Primeros pasos.

Cuatro pasos para pasar de recién llegado a contribuidor.

  1. Explora la organización en GitHub

    Revisa los issues abiertos con la etiqueta good first issue o help wanted en github.com/{{ site.data.github.org }}. ¿No hay ningún issue? Abre uno y describe lo que quieres abordar.

  2. Preséntate en Slack

    Únete a la comunidad en Slack, saluda en #general, haz preguntas y descubre qué grupo de trabajo encaja con tu perfil e intereses.

  3. Fork → rama → PR

    Haz un fork del repositorio correspondiente, crea una rama de funcionalidad y abre un pull request. Un maintainer lo revisará, te dará feedback y te guiará en el proceso.

  4. ¿Cambios más grandes? Abre primero una RFC

    Para nuevos pilares, cambios incompatibles, cambios de puntuación o de gobernanza, redacta una RFC en GitHub Discussions. La comunidad la revisa antes de empezar la implementación. Así las decisiones son trazables.

Grupos de trabajo.

Los grupos de trabajo son equipos temáticos que construyen partes concretas de WAF++. Cualquiera puede proponer uno: solo hace falta una carta, al menos una persona que lo lidere y un maintainer que lo patrocine.

Encuentra un GT

Consulta las propuestas de grupos abiertas en GitHub Discussions y únete al canal correspondiente en Slack. Puedes contribuir sin dedicación a tiempo completo.

Crea un GT

Redacta una carta en una discusión de GitHub, busca un maintainer que lo patrocine y anúncialo en Slack. Un grupo puede centrarse en cualquier ámbito: un pilar, una cuestión de herramientas, un enfoque de puntuación.

Entrega resultados

Los resultados de los grupos vuelven como PR y RFC. Todo resultado es público, trazable y citable, en coherencia con los principios de transparencia de WAF++.

Ciclo de vida de las funcionalidades.

Cada capacidad de WAF++ pasa por un ciclo de vida claro. Cada etapa depende del proceso RFC/ADR, para que los usuarios sepan siempre cuán madura es una funcionalidad y qué esperar antes de adoptarla.

Closed Alpha

Exploración privada

Un pequeño grupo de early adopters prueba la capacidad en entornos controlados. La API, el modelo de puntuación o la interfaz de la CLI son inestables a propósito y pueden cambiar sin aviso.

Cómo entra
  • Una RFC en borrador o abierta define el experimento
  • Grupo de acceso anticipado solo por invitación
  • El feedback impulsa iteraciones rápidas
Ver RFC en borrador →
Alpha

Prueba en abierto

La capacidad está disponible para cualquiera que quiera probarla. Las interfaces son mayormente estables, pero aún puede haber cambios incompatibles según el feedback de la comunidad.

Cómo entra
  • RFC aceptada con alcance alfa
  • Documentación pública y notas de versión disponibles
  • GitHub Discussions recoge el feedback
Unirse a las discusiones alfa →
Beta

Uso en producción

La capacidad está completa y lista para producción en los casos de uso documentados. Puede haber ajustes menores, pero los cambios incompatibles requieren una guía de migración explícita.

Cómo entra
  • RFC aceptada e implementación fusionada
  • Un ADR documenta los criterios de preparación para producción
  • Revisión de seguridad, rendimiento y compatibilidad superada
Seguir las RFC aceptadas →
GA

Disponibilidad general

La capacidad tiene soporte completo, está cubierta por la política de estabilidad y se recomienda a todos los usuarios. Se mantiene con actualizaciones retrocompatibles y periodos de obsolescencia claros.

Cómo entra
  • El estado de la RFC pasa a implemented
  • Un ADR final ratifica el contrato estable
  • Se incorpora al ciclo oficial de versiones
Ver las RFC implementadas →

Cada etapa está vinculada al proceso RFC/ADR. Cuando se acepta una RFC, se activa la etapa alfa o beta; cuando se marca como implemented , la capacidad queda lista para GA. Consulta el panorama completo en el seguimiento de RFC o propón el siguiente cambio en GitHub Discussions.

El proceso RFC.

Los cambios importantes pasan por una RFC (Request for Comments). El proceso es ligero, pero garantiza que cada decisión la revise la comunidad y quede documentada.

Borrador
Abre una discusión en GitHub con tu propuesta
→
Revisión
La comunidad y los maintainers comentan y afinan
→
Decisión
TSC o lazy consensus, documentado públicamente
→
Implementación
PR fusionado, registro de cambios actualizado
Ver el seguimiento de RFC

Ninguna contribución es demasiado pequeña.

Corregir una errata, aclarar un comentario, hacer una revisión: todo hace avanzar el framework. WAF++ se construye en público y la comunidad siempre está abierta.
