Un puente seguro, no un segundo sistema de autenticación.

El puente reutiliza la identidad, los permisos y los registros de auditoría de WOMBATpass. Valida, actúa como proxy y filtra; nunca almacena secretos cloud ni contraseñas del IdP.

Agnóstico respecto al IdP

Sin integración directa con Keycloak, Entra u Okta. El puente confía en los tokens emitidos por wafpass-server, que ya gestiona los flujos OIDC y SAML.

Introspección de tokens

Cada nueva conexión SSE se valida contra GET /auth/me. Detección inmediata de revocaciones y sin necesidad de compartir secretos JWT.

Herramientas con mínimo privilegio

tools/list se filtra según el rol del usuario autenticado. Los endpoints solo para administradores son invisibles para los ingenieros, y la autorización por fila se aplica en cada llamada al backend.

Propagación del contexto

La cabecera original Authorization: Bearer se reenvía a WOMBATpass en cada solicitud, preservando la identidad del usuario y la atribución en la auditoría.

Generado desde OpenAPI

Al arrancar, el puente obtiene /openapi.json y registra las operaciones seguras como herramientas MCP tipadas con argumentos validados por Pydantic.

stdio o SSE

Ejecuta el puente como proceso stdio local para Claude Desktop o expónlo por HTTP/SSE para hosts MCP remotos y clientes basados en navegador.

Conecta Claude Desktop en minutos.

Instala el puente, inicia sesión una vez y apunta Claude Desktop al comando stdio. Sin certificados, sin puertos abiertos, sin autenticación adicional.

1. Instalar y configurar 
git clone https://github.com/WAF2p/wafpass-mcp.git
cd wafpass-mcp
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"

wafpass-mcp-configure
# Enter WOMBATpass API URL, username and password
2. Configuración de Claude Desktop (stdio) 
{
  "mcpServers": {
    "wafpass": {
      "command": "/path/to/wafpass-mcp/.venv/bin/wafpass-mcp-stdio"
    }
  }
}
3. Docker Compose (alternativa) 
# From the Wombat repository root
docker compose up -d wafpass-mcp
docker compose logs -f wafpass-mcp

# SSE endpoint: http://localhost:3001/sse
# Override WAFPASS_TOKEN_MODE or WAFPASS_JWT_SECRET in .env

Cómo encaja el puente.

El usuario se autentica a través del IdP, intercambia tokens con WOMBATpass y lleva el mismo token Bearer al host MCP. El puente reenvía las solicitudes y filtra las herramientas por rol.
