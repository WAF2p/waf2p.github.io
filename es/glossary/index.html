A
Agentic framework

Relativo a agentes de IA autónomos que planifican, actúan e interactúan con sistemas sin instrucción humana directa. En WAF++, el pilar Agéntico (pilar 8) define controles para gobernar estos agentes en cargas de trabajo en producción.

Ver también: Pillar, Los 8 pilares

Antora herramientas

El generador de sitios estáticos usado para construir la documentación de WAF++ a partir de fuentes AsciiDoc. Antora gestiona el versionado de componentes, la navegación y la publicación; la documentación de WAF++ está en /docs/ y se genera a partir del repositorio framework .

Ver también: AsciiDoc

AsciiDoc herramientas

El lenguaje de marcado usado para escribir la documentación del framework WAF++. Similar a Markdown, pero con una semántica más rica para documentación estructurada. Todos los archivos de modules/ROOT/pages/ usan AsciiDoc (extensión.adoc ).

Assessment framework

Una evaluación estructurada de una carga de trabajo cloud frente a los controles de WAF++ en todos los pilares aplicables. El resultado es un conjunto de hallazgos por control y una puntuación PASS por pilar y agregada.

Ver también: Workload, PASS model

C
Charter gobernanza

Un documento breve que define el propósito, el alcance, los entregables, los líderes y el canal de comunicación de un grupo de trabajo. Se necesita una carta para que un grupo sea reconocido oficialmente.

Ver también: Working Group

Control framework

Un requisito concreto y verificable dentro de un pilar. Cada control tiene un ID único, una descripción, una pregunta de evaluación y una justificación. Los controles son la unidad atómica del framework WAF++: una carga de trabajo cumple un control o no lo cumple.

Ver también: Control ID, Pillar, Controls library

Control ID framework

El identificador único de un control de WAF++, con el patrón WAF-[PILLAR]-[NUMBER]. Ejemplo: WAF-SOV-010 es el primer control del pilar Soberanía. La abreviatura del pilar es un código de tres letras (p. ej., SEC para Seguridad, SOV para Soberanía, AGN para Agéntico). Los IDs de control son estables: una vez publicados, nunca cambian ni se reutilizan.

Controls library framework

La colección completa de controles de WAF++, almacenada como archivos YAML estructurados en el repositorio framework en modules/controls/. La biblioteca abarca ya 8 pilares con más de 100 controles.

Contributor gobernanza

Cualquier persona que envíe un pull request, abra un issue, participe en una GitHub Discussion, proponga una RFC o contribuya de otra forma a cualquier repositorio de WAF++. No se necesitan permisos formales: cualquier usuario de GitHub puede contribuir.

Ver también: Maintainer

D
Dual-licence model gobernanza

WAF++ usa dos licencias: Apache License 2.0 para código, herramientas y esquemas; Creative Commons Attribution 4.0 (CC BY 4.0) para la documentación y el contenido escrito. Esto permite una amplia reutilización garantizando la atribución. Consulta la página legal para más detalles.

F
Finding framework

El resultado de evaluar un control sobre una carga de trabajo. Un hallazgo puede ser cumplido, no cumplidoo no aplicable. Los hallazgos son el resultado bruto de una evaluación y después se agregan en una puntuación PASS.

Foundation-ready gobernanza

Un estándar de calidad del modelo de gobernanza de WAF++ que indica que la estructura, las políticas y la transparencia del proyecto cumplen los requisitos para donarlo a una fundación open source (p. ej., CNCF, Apache Software Foundation). Es un objetivo declarado de las versiones v1.x de WAF++.

G
Governance gobernanza

El conjunto de reglas, procesos y roles que determinan cómo se toman las decisiones en el proyecto WAF++. La gobernanza de WAF++ está documentada públicamente y cubre: el proceso RFC, la composición y las votaciones del TSC, los mandatos de los maintainers, las reglas de los grupos de trabajo y la aplicación del código de conducta.

Ver también: TSC, RFC, Página de gobernanza y comunidad

I
IaC — Infrastructure as Code framework

La práctica de gestionar y aprovisionar infraestructura cloud mediante archivos de configuración legibles por máquina en lugar de procesos manuales. Es relevante para varios pilares de WAF++, en especial Excelencia operativa y Seguridad.

L
Lazy consensus proceso

Un mecanismo ligero de toma de decisiones para cambios compatibles o de menor riesgo. La propuesta se publica con un plazo mínimo de revisión de 5 días hábiles. Si nadie plantea una objeción fundada, se considera aceptada. Para cambios importantes se recurre a la votación del TSC.

Ver también: TSC, RFC

M
Maintainer gobernanza

Un contribuidor con permisos de merge en uno o varios repositorios de WAF++. Los maintainers revisan PR, aprueban o rechazan RFC y son responsables de la calidad y la dirección de su área. Los mandatos duran 12 meses y son renovables. Más de 90 días de inactividad pueden llevar al estado de emérito.

Ver también: Página de roles y miembros

P
PASS model puntuación

El modelo de puntuación de WAF++. PASS corresponde a los cuatro niveles de logro: Pioneer, Advanced, Solid, Starter. Cada nivel corresponde a un grado de cumplimiento de controles dentro de un pilar. El modelo PASS es la especificación normativa de puntuación; consulta la página de WAFPass para más detalles.

Ver también: PASS score, Scoring tier

PASS score puntuación

El resultado de aplicar el modelo PASS a una evaluación. Una carga de trabajo recibe una puntuación por pilar y una puntuación global agregada. Las puntuaciones se expresan como niveles (Pioneer / Advanced / Solid / Starter), no como porcentajes, para reflejar la madurez cualitativa y no solo la tasa de aprobación.

Ver también: PASS model

Pillar framework

Una de las ocho dimensiones de evaluación de WAF++. Cada pilar agrupa controles que abordan un aspecto concreto de la calidad de las cargas de trabajo cloud. Los ocho pilares son: Security, Reliability, Performance Efficiency, Cost Optimisation, Operational Excellence, Sustainability, Sovereign y Agentic.

Ver también: Control, Los 8 pilares

Pillar score puntuación

El nivel PASS alcanzado por un pilar, derivado de la tasa de cumplimiento de controles y de los controles obligatorios de ese pilar. Las puntuaciones por pilar se agregan en la puntuación PASS global.

R
RFC — Request for Comments proceso

Una propuesta pública de un cambio importante en el framework, la gobernanza, las herramientas o el modelo de puntuación de WAF++. Las RFC se abren como GitHub Discussions, la comunidad las revisa durante al menos 5 días hábiles y se deciden por votación del TSC o lazy consensus. Cada RFC recibe un ID secuencial (RFC-NNNN) y se registra en el seguimiento de RFC.

Ver también: RFC lifecycle, Lazy consensus

RFC lifecycle proceso

Los estados definidos por los que pasa una RFC: draft (en redacción) → open (abierta a revisión de la comunidad) → accepted (decisión tomada: adelante) → implemented (entregada y cerrada). Resultados alternativos: rejected o withdrawn. Todos los estados y transiciones están documentados públicamente.

S
Scoring tier puntuación

Uno de los cuatro niveles del modelo PASS. En orden descendente: Pioneer (el más alto), Advanced, Solid, Starter (base). Los niveles reflejan la amplitud y la profundidad del cumplimiento de controles, no solo el número de controles superados.

Ver también: PASS model

Sovereign pillar framework

El 7.º pilar de WAF++, que cubre la soberanía de los datos, el cumplimiento normativo y el control jurisdiccional. Se añadió con 10 controles iniciales (WAF-SOV-010 a WAF-SOV-100). Especialmente relevante para sectores regulados y cargas de trabajo en la UE.

T
TSC — Technical Steering Committee gobernanza

El órgano de gobierno del proyecto WAF++. El TSC es responsable de la dirección técnica, las decisiones sobre RFC y el nombramiento de maintainers. Sus miembros tienen mandatos renovables de 12 meses. La composición sigue el principio de «primero los contribuidores activos» y un equilibrio neutral entre proveedores. Todas las decisiones del TSC se documentan públicamente.

Ver también: Gobernanza y comunidad, Roles y miembros

V
Vendor-neutral framework

Un principio de diseño fundamental de WAF++: los pilares, los controles y el modelo de puntuación se aplican por igual a cargas de trabajo en cualquier proveedor cloud (AWS, Azure, GCP y otros). Ningún control es específico de un proveedor salvo que se indique expresamente. Esto permite evaluaciones coherentes entre proveedores y evita quedar atado a la metodología de revisión de uno solo.

W
WAF++ framework

Well-Architected Framework Plus Plus. Un framework open source y neutral respecto al proveedor para evaluar y mejorar la calidad de las cargas de trabajo cloud. WAF++ amplía las revisiones well-architected convencionales con un modelo de puntuación transparente e impulsado por la comunidad (PASS) y una biblioteca de controles legible por máquina con 8 pilares y más de 100 controles.

WAFPass herramientas

El conjunto oficial de herramientas de evaluación de WAF++: CLI, servidor, panel y scorecard web. WAFPass consume la biblioteca de controles, evalúa una carga de trabajo y genera un informe de puntuación PASS. Versión actual: v1.1.0.

Working Group (WG) gobernanza

Un equipo de contribuidores centrado en un tema dentro de WAF++. Los grupos de trabajo construyen partes concretas del framework (un pilar, un componente de herramientas, una arquitectura de referencia) y entregan resultados como PR y RFC. Cualquier contribuidor puede proponer un grupo con una carta, un líder y un maintainer patrocinador.

Ver también: Charter, Contribuir

Workload framework

La aplicación, el servicio o el sistema cloud que se evalúa con WAF++. Una carga de trabajo tiene un alcance definido (p. ej., un microservicio, una plataforma de datos, un producto completo) y se evalúa frente a los controles de WAF++ aplicables. El alcance se define antes de empezar la evaluación.

Ver también: Assessment
