Cosa richiede un RFC?

Non tutte le modifiche richiedono un RFC, solo quelle rilevanti. Usa la tabella qui sotto per decidere.

Tipo di modifica Serve un RFC? Processo
Nuovo pilastro o rimozione di un pilastro Sì RFC → voto del TSC → PR
Modifiche al modello di punteggio (livelli PASS, pesi) Sì RFC → voto del TSC → PR
Modifica incompatibile allo schema o agli ID dei controlli Sì RFC → voto del TSC → PR
Proposta di un nuovo gruppo di lavoro Sì RFC → lazy consensus → statuto pubblicato
Modifiche a governance o ruoli Sì RFC → maggioranza qualificata del TSC
Nuovo controllo (compatibile, aggiuntivo) Consigliato PR con link alla discussione, lazy consensus
Formulazione della documentazione, refusi, traduzioni No Solo PR
Contenuti del sito web, articoli del blog No Solo PR

Flusso degli stati di un RFC.

Ogni RFC segue lo stesso percorso documentato, dalla prima bozza alla decisione finale.

draft
Chi propone scrive la proposta in GitHub Discussions
→
open
Almeno 5 giorni lavorativi aperta ai commenti della community
→
accepted
Voto del TSC o lazy consensus, documentato pubblicamente
→
implemented
PR unita, voce aggiunta al changelog, RFC chiuso
Esiti alternativi: rejected (non accettato dopo la revisione), withdrawn (ritirato da chi lo ha proposto). Entrambi sono documentati con le motivazioni.

Come scrivere un buon RFC.

Tre aspetti che fanno la differenza tra un RFC che procede spedito e uno che si arena.

Descrivi il problema, non la soluzione

Parti da ciò che non funziona o manca, non da ciò che vuoi costruire. I revisori devono concordare che il problema sia reale prima di valutare la tua soluzione. Chiarisci il «perché» prima del «cosa».

Mostra compromessi e alternative

Un buon RFC spiega cos'altro è stato valutato e perché è stato scartato. Si risparmiano cicli di revisione e i futuri maintainer hanno contesto quando chi ha proposto l'RFC non è più coinvolto.

Sii preciso sull'impatto

Chi è coinvolto? Quali repository, file o contratti pubblici cambiano? Più chiaro è l'ambito, prima la community può dare feedback utili e un maintainer può decidere.
