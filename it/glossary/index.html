A
Agentic framework

Relativo ad agenti di IA autonomi che pianificano, agiscono e interagiscono con i sistemi senza istruzioni umane dirette. In Wombat il pilastro Agentico (pilastro 8) definisce i controlli per governare questi agenti nei workload in produzione.

Vedi anche: Pillar, Gli 8 pilastri

Antora strumenti

Il generatore di siti statici usato per creare la documentazione Wombat dai sorgenti AsciiDoc. Antora gestisce il versionamento dei componenti, la navigazione e la pubblicazione: la documentazione Wombat si trova in /docs/ ed è generata dal repository framework .

Vedi anche: AsciiDoc

AsciiDoc strumenti

Il linguaggio di markup usato per scrivere la documentazione del framework Wombat. Simile a Markdown ma con una semantica più ricca per la documentazione strutturata. Tutti i file in modules/ROOT/pages/ usano AsciiDoc (estensione.adoc ).

Assessment framework

Una valutazione strutturata di un workload cloud rispetto ai controlli Wombat su tutti i pilastri applicabili. Il risultato è un insieme di finding per controllo e un punteggio PASS per pilastro e complessivo.

Vedi anche: Workload, PASS model

C
Charter governance

Un breve documento che definisce scopo, ambito, risultati, lead e canale di comunicazione di un gruppo di lavoro. Lo statuto è necessario perché un gruppo venga riconosciuto ufficialmente.

Vedi anche: Working Group

Control framework

Un requisito specifico e verificabile all'interno di un pilastro. Ogni controllo ha un ID univoco, una descrizione, una domanda di valutazione e una motivazione. I controlli sono l'unità atomica del framework Wombat: un workload soddisfa un controllo oppure no.

Vedi anche: Control ID, Pillar, Controls library

Control ID framework

L'identificativo univoco di un controllo Wombat, secondo lo schema WAF-[PILLAR]-[NUMBER]. Esempio: WAF-SOV-010 è il primo controllo del pilastro Sovranità. L'abbreviazione del pilastro è un codice di tre lettere (ad es. SEC per Sicurezza, SOV per Sovranità, AGN per Agentico). Gli ID dei controlli sono stabili: una volta pubblicati non cambiano né vengono riutilizzati.

Controls library framework

La raccolta completa dei controlli Wombat, archiviata come file YAML strutturati nel repository framework in modules/controls/. La libreria copre ora 8 pilastri con oltre 100 controlli.

Contributor governance

Chiunque invii una pull request, apra una issue, partecipi a una GitHub Discussion, proponga un RFC o contribuisca in altro modo a un repository Wombat. Non servono permessi formali: qualsiasi utente GitHub può contribuire.

Vedi anche: Maintainer

D
Dual-licence model governance

Wombat usa due licenze: Apache License 2.0 per codice, strumenti e schemi; Creative Commons Attribution 4.0 (CC BY 4.0) per la documentazione e i contenuti scritti. Ciò consente un ampio riutilizzo garantendo l'attribuzione. Vedi la pagina Note legali per i dettagli.

F
Finding framework

Il risultato della valutazione di un controllo su un workload. Un finding è soddisfatto, non soddisfattooppure non applicabile. I finding sono l'output grezzo di una valutazione e vengono poi aggregati in un punteggio PASS.

Foundation-ready governance

Uno standard di qualità del modello di governance di Wombat: struttura, policy e trasparenza del progetto soddisfano i requisiti per la donazione a una fondazione open source (ad es. CNCF, Apache Software Foundation). È un obiettivo dichiarato delle release v1.x di Wombat.

G
Governance governance

L'insieme di regole, processi e ruoli che determinano come si prendono le decisioni nel progetto Wombat. La governance di Wombat è documentata pubblicamente e comprende: processo RFC, composizione e votazioni del TSC, mandati dei maintainer, regole dei gruppi di lavoro e applicazione del codice di condotta.

Vedi anche: TSC, RFC, Pagina Governance e community

I
IaC — Infrastructure as Code framework

La pratica di gestire e predisporre l'infrastruttura cloud tramite file di configurazione leggibili dalle macchine anziché processi manuali. Rilevante per diversi pilastri di Wombat, in particolare Eccellenza operativa e Sicurezza.

L
Lazy consensus processo

Un meccanismo decisionale leggero per modifiche non incompatibili o a basso rischio. Una proposta viene pubblicata con una finestra di revisione di almeno 5 giorni lavorativi. Se non emergono obiezioni fondate, la proposta si considera accettata. Per le modifiche importanti si ricorre invece al voto del TSC.

Vedi anche: TSC, RFC

M
Maintainer governance

Un contributor con permessi di merge su uno o più repository Wombat. I maintainer revisionano le PR, approvano o respingono gli RFC e sono responsabili della qualità e della direzione della propria area. Il mandato dura 12 mesi ed è rinnovabile. Oltre 90 giorni di inattività possono portare allo stato di emerito.

Vedi anche: Pagina Ruoli e membri

P
PASS model punteggio

Il modello di punteggio di Wombat. PASS indica i quattro livelli di risultato: Pioneer, Advanced, Solid, Starter. Ogni livello corrisponde a un grado di soddisfazione dei controlli all'interno di un pilastro. Il modello PASS è la specifica normativa del punteggio: vedi la pagina WOMBATpass per i dettagli.

Vedi anche: PASS score, Scoring tier

PASS score punteggio

Il risultato dell'applicazione del modello PASS a una valutazione. Un workload riceve un punteggio per pilastro e un punteggio complessivo aggregato. I punteggi sono espressi come livelli (Pioneer / Advanced / Solid / Starter), non come percentuali, per riflettere la maturità qualitativa e non solo i tassi di superamento.

Vedi anche: PASS model

Pillar framework

Una delle otto dimensioni di valutazione di Wombat. Ogni pilastro raggruppa controlli su uno specifico aspetto di qualità dei workload cloud. Gli otto pilastri sono: Security, Reliability, Performance Efficiency, Cost Optimisation, Operational Excellence, Sustainability, Sovereign e Agentic.

Vedi anche: Control, Gli 8 pilastri

Pillar score punteggio

Il livello PASS raggiunto da un singolo pilastro, ricavato dal tasso di soddisfazione dei controlli e dagli eventuali controlli obbligatori di quel pilastro. I punteggi dei pilastri vengono aggregati nel punteggio PASS complessivo.

R
RFC — Request for Comments processo

Una proposta pubblica di modifica rilevante al framework, alla governance, agli strumenti o al modello di punteggio di Wombat. Gli RFC vengono aperti come GitHub Discussions, revisionati dalla community per almeno 5 giorni lavorativi e poi decisi con voto del TSC o lazy consensus. Ogni RFC riceve un ID sequenziale (RFC-NNNN) ed è tracciato nel tracker degli RFC.

Vedi anche: RFC lifecycle, Lazy consensus

RFC lifecycle processo

Gli stati definiti che un RFC attraversa: draft (in stesura) → open (aperto alla revisione della community) → accepted (decisione presa: si procede) → implemented (rilasciato e chiuso). Esiti alternativi: rejected o withdrawn. Tutti gli stati e le transizioni sono documentati pubblicamente.

S
Scoring tier punteggio

Uno dei quattro livelli del modello PASS. In ordine decrescente: Pioneer (il più alto), Advanced, Solid, Starter (base). I livelli riflettono ampiezza e profondità della soddisfazione dei controlli, non solo il numero di controlli superati.

Vedi anche: PASS model

Sovereign pillar framework

Il 7° pilastro di Wombat, dedicato a sovranità dei dati, conformità normativa e controllo giurisdizionale. Introdotto con 10 controlli iniziali (WAF-SOV-010 a WAF-SOV-100). Particolarmente rilevante per i settori regolamentati e i workload nell'UE.

T
TSC — Technical Steering Committee governance

L'organo di governo del progetto Wombat. Il TSC è responsabile della direzione tecnica, delle decisioni sugli RFC e della nomina dei maintainer. I membri hanno mandati rinnovabili di 12 mesi. La composizione segue il principio «prima i contributor attivi» e un equilibrio neutrale tra fornitori. Tutte le decisioni del TSC sono documentate pubblicamente.

Vedi anche: Governance e community, Ruoli e membri

V
Vendor-neutral framework

Un principio di design fondamentale di Wombat: pilastri, controlli e modello di punteggio si applicano allo stesso modo ai workload di qualsiasi cloud provider (AWS, Azure, GCP e altri). Nessun controllo è specifico di un provider se non indicato esplicitamente. Ciò consente valutazioni coerenti tra provider ed evita il lock-in nella metodologia di revisione di un singolo fornitore.

W
Wombat framework

Cloud Governance & IaC Validation. Un framework open source e neutrale rispetto ai fornitori per valutare e migliorare la qualità dei workload cloud. Wombat estende le classiche revisioni well-architected con un modello di punteggio trasparente e guidato dalla community (PASS) e una libreria di controlli leggibile dalle macchine su 8 pilastri e oltre 100 controlli.

WOMBATpass strumenti

La suite ufficiale di strumenti di valutazione di Wombat: CLI, server, dashboard e scorecard web. WOMBATpass usa la libreria dei controlli, valuta un workload e produce un report di punteggio PASS. Release attuale: v1.1.0.

Working Group (WG) governance

Un team di contributor dedicato a un tema all'interno di Wombat. I gruppi di lavoro sviluppano parti specifiche del framework — un pilastro, un componente degli strumenti, un'architettura di riferimento — e consegnano i risultati come PR e RFC. Qualsiasi contributor può proporre un gruppo con uno statuto, un lead e un maintainer sponsor.

Vedi anche: Charter, Contribuire

Workload framework

L'applicazione, il servizio o il sistema cloud valutato con Wombat. Un workload ha un ambito definito (ad es. un microservizio, una piattaforma dati, un intero prodotto) ed è valutato rispetto ai controlli Wombat applicabili. L'ambito viene definito prima dell'inizio della valutazione.

Vedi anche: Assessment

Apri una issue sui contenuti su GitHub o proponi una definizione su Slack. Il glossario cresce con la community: ogni aggiunta rende il framework più facile da usare.
