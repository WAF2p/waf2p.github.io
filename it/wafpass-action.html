Un passaggio. Visibilità completa.

L'action gestisce installazione della CLI, scansione, caricamento dei risultati e applicazione delle policy, così il tuo team può concentrarsi sui rilasci.

Installazione automatica della CLI

Installa automaticamente l'ultima versione di wafpass-core da PyPI, oppure usa una sorgente pip personalizzata o un binario preinstallato.

Scansione multi-IaC

Scansiona file Terraform, Bicep, CDK o Pulumi in un solo passaggio. Supporta più percorsi e il JSON del piano Terraform per una panoramica delle modifiche.

Invio al server

Carica l'intero wafpass-result.json su POST /api/v1/runs così dashboard e pacchetti di evidenze restano aggiornati.

Gate delle policy

Policy fail_on configurabili, da never a critical. Il passaggio fallisce solo dopo che il risultato è stato salvato in modo sicuro sul server.

Autenticazione flessibile

Usa un token Bearer per gli utenti interattivi o una chiave API di ingestione per le esecuzioni CI/CD headless. Entrambi vengono inoltrati in modo sicuro al server.

Metadati CI/CD

Contrassegna le esecuzioni come is_cicd: true con triggered_by: github-actions e passa automaticamente branch, SHA del commit, progetto e stage.

Aggiungila a qualsiasi workflow.

Fai il checkout del repo, esegui l'action e mostra i risultati di conformità dove il tuo team lavora già.

.github/workflows/wafpass.yml
{% raw %}
name: WAF++ PASS Scan

on:
  push:
    branches: [main, develop]
  pull_request:

jobs:
  wafpass:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Run WAF++ PASS
        uses: WAF2p/wafpass-action@v0.1.1
        with:
          server_url: ${{ vars.WAFPASS_SERVER_URL }}
          api_key: ${{ secrets.WAFPASS_API_KEY }}
          scan_path: ./infra
          iac_framework: terraform
          project: ${{ github.repository }}
          stage: ${{ github.ref_name == 'main' && 'prod' || 'dev' }}
          fail_on: high
          upload_source: true
{% endraw %}
Esempio multi-cloud / monorepo
