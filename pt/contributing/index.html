Formas de contribuir.

Código, conteúdo, comunidade: escolha o que combina com suas habilidades e seu tempo.

PRs e issues

Corrija bugs, implemente controles, melhore as ferramentas. Cada PR é revisado por um mantenedor e vinculado a uma decisão.

Documentação e padrões

Escreva documentação dos pilares, arquiteturas de referência, padrões de boas práticas ou exemplos concretos de projetos reais.

Revisão de RFCs

Comente RFCs abertas, proponha alternativas ou vote em decisões do framework. Cada voz conta, especialmente a perspectiva prática.

Localização

Ajude a traduzir o conteúdo para alemão, inglês ou outros idiomas. O Wombat deve ser acessível à comunidade de nuvem global.

Grupos de trabalho

Participe ou proponha um grupo de trabalho sobre um pilar específico, o modelo de pontuação, a biblioteca de controles ou uma arquitetura de referência.

Palestras e BoFs

Apresente o Wombat numa conferência, organize uma sessão Birds-of-a-Feather ou conduza um workshop da comunidade. Experiência prática vale ouro.

Primeiros passos.

Quatro passos para ir de recém-chegado a contribuidor.

  1. Explore a organização no GitHub

    Veja as issues abertas com a etiqueta good first issue ou help wanted em github.com/{{ site.data.github.org }}. Nenhuma issue ainda? Abra uma e descreva o que você quer resolver.

  2. Apresente-se no Slack

    Entre na comunidade no Slack, diga oi em #general, tire dúvidas e descubra qual grupo de trabalho combina com seu perfil e interesses.

  3. Fork → branch → PR

    Faça um fork do repositório adequado, crie uma branch de funcionalidade e abra um pull request. Um mantenedor vai revisá-lo, dar feedback e orientar você no processo.

  4. Mudanças maiores? Abra primeiro uma RFC

    Para novos pilares, mudanças incompatíveis, mudanças de pontuação ou de governança, escreva uma RFC no GitHub Discussions. A comunidade a revisa antes de a implementação começar. Assim as decisões continuam rastreáveis.

Grupos de trabalho.

Grupos de trabalho são equipes temáticas que constroem partes específicas do Wombat. Qualquer pessoa pode propor um: basta uma carta, pelo menos uma liderança e um mantenedor como patrocinador.

Encontre um GT

Veja as propostas de grupos abertas no GitHub Discussions e entre no canal correspondente no Slack. Você pode contribuir sem dedicação em tempo integral.

Crie um GT

Escreva uma carta numa discussão no GitHub, encontre um mantenedor patrocinador e anuncie no Slack. Um grupo pode ter qualquer escopo: um único pilar, uma questão de ferramentas, uma abordagem de pontuação.

Entregue resultados

Os resultados dos grupos voltam como PRs e RFCs. Todo resultado é público, rastreável e citável, em linha com os princípios de transparência do Wombat.

Ciclo de vida das funcionalidades.

Cada capacidade do Wombat passa por um ciclo de vida claro. Cada etapa depende do processo de RFC/ADR, para que os usuários sempre saibam o quão madura é uma funcionalidade e o que esperar antes de adotá-la.

Closed Alpha

Exploração privada

Um pequeno grupo de early adopters testa a capacidade em ambientes controlados. A API, o modelo de pontuação ou a interface da CLI são instáveis de propósito e podem mudar sem aviso.

Como entra
  • Uma RFC em rascunho ou aberta define o experimento
  • Grupo de acesso antecipado só por convite
  • O feedback impulsiona iterações rápidas
Ver RFCs em rascunho →
Alpha

Teste aberto

A capacidade está disponível para qualquer pessoa que queira experimentá-la. As interfaces são em grande parte estáveis, mas ainda podem ocorrer mudanças incompatíveis com base no feedback da comunidade.

Como entra
  • RFC aceita com escopo alfa
  • Documentação pública e notas de versão disponíveis
  • O GitHub Discussions reúne o feedback
Participar das discussões alfa →
Beta

Uso em produção

A capacidade está completa e pronta para produção nos casos de uso documentados. Ajustes menores ainda podem acontecer, mas mudanças incompatíveis exigem orientação de migração explícita.

Como entra
  • RFC aceita e implementação mesclada
  • Um ADR documenta os critérios de prontidão para produção
  • Revisão de segurança, desempenho e compatibilidade aprovada
Acompanhar RFCs aceitas →
GA

Disponibilidade geral

A capacidade tem suporte completo, está coberta pela política de estabilidade e é recomendada a todos os usuários. É mantida com atualizações retrocompatíveis e prazos claros de descontinuação.

Como entra
  • O status da RFC passa para implemented
  • Um ADR final ratifica o contrato estável
  • Incluída no ciclo oficial de versões
Ver RFCs implementadas →

Cada etapa está ligada ao processo de RFC/ADR. Quando uma RFC é aceita, ela aciona a etapa alfa ou beta; quando é marcada como implemented , a capacidade fica pronta para GA. Veja o panorama completo no acompanhamento de RFCs ou proponha a próxima mudança no GitHub Discussions.

O processo de RFC.

Mudanças relevantes passam por uma RFC (Request for Comments). O processo é leve, mas garante que cada decisão seja revisada pela comunidade e documentada.

Rascunho
Abra uma discussão no GitHub com sua proposta
→
Revisão
A comunidade e os mantenedores comentam e refinam
→
Decisão
TSC ou lazy consensus, documentado publicamente
→
Implementação
PR mesclado, registro de alterações atualizado
Ver o acompanhamento de RFCs

Nenhuma contribuição é pequena demais.

Corrigir um erro de digitação, esclarecer um comentário, fazer uma revisão: tudo faz o framework avançar. O Wombat é construído em público e a comunidade está sempre aberta.
