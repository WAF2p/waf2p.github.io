O que exige uma RFC?

Nem toda mudança precisa de uma RFC, só as relevantes. Use a tabela abaixo para decidir.

Tipo de mudança Precisa de RFC? Processo
Novo pilar ou remoção de um pilar Sim RFC → votação do TSC → PR
Mudanças no modelo de pontuação (níveis PASS, pesos) Sim RFC → votação do TSC → PR
Mudança incompatível no esquema ou nos IDs dos controles Sim RFC → votação do TSC → PR
Proposta de novo grupo de trabalho Sim RFC → lazy consensus → carta publicada
Mudanças de governança ou de papéis Sim RFC → maioria qualificada do TSC
Novo controle (compatível, aditivo) Recomendado PR com link para a discussão, lazy consensus
Redação da documentação, erros de digitação, traduções Não Só PR
Conteúdo do site, posts do blog Não Só PR

Fluxo de status de uma RFC.

Toda RFC segue o mesmo caminho documentado, do primeiro rascunho à decisão encerrada.

draft
A autoria redige a proposta no GitHub Discussions
→
open
No mínimo 5 dias úteis aberta a comentários da comunidade
→
accepted
Votação do TSC ou lazy consensus, documentada publicamente
→
implemented
PR mesclado, entrada no registro de alterações adicionada, RFC encerrada
Resultados alternativos: rejected (não aceita após revisão), withdrawn (retirada pela autoria). Ambos são documentados com os motivos.

Como escrever uma boa RFC.

Três coisas que fazem a diferença entre uma RFC que avança rápido e uma que trava.

Descreva o problema, não a solução

Comece pelo que está quebrado ou faltando, não pelo que você quer construir. Os revisores precisam concordar que o problema é real antes de avaliar a solução proposta. Explique o “porquê” antes do “o quê”.

Mostre trade-offs e alternativas

Uma boa RFC explica o que mais foi considerado e por que foi descartado. Isso poupa rodadas de revisão e dá contexto a futuros mantenedores quando a autoria original já não estiver presente.

Seja específico sobre o impacto

Quem é afetado? Quais repositórios, arquivos ou contratos públicos mudam? Quanto mais claro o escopo, mais rápido a comunidade dá feedback útil e um mantenedor decide.
