A
Agentic framework

Relativo a agentes de IA autônomos que planejam, agem e interagem com sistemas sem instrução humana direta. No WAF++, o pilar Agêntico (pilar 8) define controles para governar esses agentes em workloads de produção.

Veja também: Pillar, Os 8 pilares

Antora ferramentas

O gerador de sites estáticos usado para construir a documentação do WAF++ a partir de fontes AsciiDoc. O Antora cuida do versionamento de componentes, da navegação e da publicação; a documentação do WAF++ fica em /docs/ e é gerada a partir do repositório framework .

Veja também: AsciiDoc

AsciiDoc ferramentas

A linguagem de marcação usada para escrever a documentação do framework WAF++. Semelhante ao Markdown, mas com semântica mais rica para documentação estruturada. Todos os arquivos em modules/ROOT/pages/ usam AsciiDoc (extensão.adoc ).

Assessment framework

Uma avaliação estruturada de um workload em nuvem com base nos controles do WAF++ em todos os pilares aplicáveis. O resultado é um conjunto de achados por controle e uma pontuação PASS por pilar e agregada.

Veja também: Workload, PASS model

C
Charter governança

Um documento curto que define o propósito, o escopo, as entregas, as lideranças e o canal de comunicação de um grupo de trabalho. A carta é obrigatória para que o grupo seja reconhecido oficialmente.

Veja também: Working Group

Control framework

Um requisito específico e testável dentro de um pilar. Cada controle tem um ID único, uma descrição, uma pergunta de avaliação e uma justificativa. Os controles são a unidade atômica do framework WAF++: um workload atende a um controle ou não.

Veja também: Control ID, Pillar, Controls library

Control ID framework

O identificador único de um controle do WAF++, seguindo o padrão WAF-[PILLAR]-[NUMBER]. Exemplo: WAF-SOV-010 é o primeiro controle do pilar Soberania. A abreviatura do pilar é um código de três letras (ex.: SEC para Segurança, SOV para Soberania, AGN para Agêntico). Os IDs de controle são estáveis: uma vez publicados, nunca mudam nem são reutilizados.

Controls library framework

A coleção completa de controles do WAF++, armazenada como arquivos YAML estruturados no repositório framework em modules/controls/. A biblioteca já abrange 8 pilares com mais de 100 controles.

Contributor governança

Qualquer pessoa que envie um pull request, abra uma issue, participe de uma GitHub Discussion, proponha uma RFC ou contribua de outra forma para um repositório do WAF++. Não são necessárias permissões formais: qualquer usuário do GitHub pode contribuir.

Veja também: Maintainer

D
Dual-licence model governança

O WAF++ usa duas licenças: Apache License 2.0 para código, ferramentas e esquemas; Creative Commons Attribution 4.0 (CC BY 4.0) para documentação e conteúdo escrito. Isso permite ampla reutilização garantindo a atribuição. Veja a página Jurídico para mais detalhes.

F
Finding framework

O resultado da avaliação de um controle para um workload. Um achado pode ser atendido, não atendidoou não aplicável. Os achados são a saída bruta de uma avaliação e depois são agregados numa pontuação PASS.

Foundation-ready governança

Um padrão de qualidade do modelo de governança do WAF++ que indica que a estrutura, as políticas e a transparência do projeto atendem aos requisitos para doação a uma fundação open source (ex.: CNCF, Apache Software Foundation). É um objetivo declarado das versões v1.x do WAF++.

G
Governance governança

O conjunto de regras, processos e papéis que determinam como as decisões são tomadas no projeto WAF++. A governança do WAF++ é documentada publicamente e abrange: processo de RFC, composição e votações do TSC, mandatos dos mantenedores, regras dos grupos de trabalho e aplicação do código de conduta.

Veja também: TSC, RFC, Página Governança e comunidade

I
IaC — Infrastructure as Code framework

A prática de gerenciar e provisionar infraestrutura em nuvem por meio de arquivos de configuração legíveis por máquina, em vez de processos manuais. Relevante para vários pilares do WAF++, em especial Excelência operacional e Segurança.

L
Lazy consensus processo

Um mecanismo leve de decisão para mudanças compatíveis ou de menor risco. A proposta é publicada com uma janela mínima de revisão de 5 dias úteis. Se não houver objeção fundamentada, é considerada aceita. Para mudanças maiores, usa-se a votação do TSC.

Veja também: TSC, RFC

M
Maintainer governança

Um contribuidor com permissão de merge em um ou mais repositórios do WAF++. Os mantenedores revisam PRs, aprovam ou rejeitam RFCs e respondem pela qualidade e direção da sua área. O mandato é de 12 meses, renovável. Mais de 90 dias de inatividade podem levar ao status de emérito.

Veja também: Página Papéis e membros

P
PASS model pontuação

O modelo de pontuação do WAF++. PASS representa os quatro níveis de desempenho: Pioneer, Advanced, Solid, Starter. Cada nível corresponde a um grau de atendimento dos controles dentro de um pilar. O modelo PASS é a especificação normativa de pontuação; veja a página do WAFPass para mais detalhes.

Veja também: PASS score, Scoring tier

PASS score pontuação

O resultado da aplicação do modelo PASS a uma avaliação. Um workload recebe uma pontuação por pilar e uma pontuação geral agregada. As pontuações são expressas em níveis (Pioneer / Advanced / Solid / Starter), não em porcentagens, para refletir a maturidade qualitativa e não apenas a taxa de aprovação.

Veja também: PASS model

Pillar framework

Uma das oito dimensões de avaliação do WAF++. Cada pilar agrupa controles que tratam de um aspecto específico da qualidade de workloads em nuvem. Os oito pilares são: Security, Reliability, Performance Efficiency, Cost Optimisation, Operational Excellence, Sustainability, Sovereign e Agentic.

Veja também: Control, Os 8 pilares

Pillar score pontuação

O nível PASS alcançado por um único pilar, derivado da taxa de atendimento dos controles e de eventuais controles obrigatórios desse pilar. As pontuações por pilar são agregadas na pontuação PASS geral.

R
RFC — Request for Comments processo

Uma proposta pública de mudança relevante no framework, na governança, nas ferramentas ou no modelo de pontuação do WAF++. As RFCs são abertas como GitHub Discussions, revisadas pela comunidade por no mínimo 5 dias úteis e depois decididas por votação do TSC ou lazy consensus. Cada RFC recebe um ID sequencial (RFC-NNNN) e é acompanhada no rastreador de RFCs.

Veja também: RFC lifecycle, Lazy consensus

RFC lifecycle processo

Os estados definidos pelos quais uma RFC passa: draft (em redação) → open (aberta para revisão da comunidade) → accepted (decisão tomada: seguir em frente) → implemented (entregue e encerrada). Resultados alternativos: rejected ou withdrawn. Todos os estados e transições são documentados publicamente.

S
Scoring tier pontuação

Um dos quatro níveis do modelo PASS. Em ordem decrescente: Pioneer (o mais alto), Advanced, Solid, Starter (base). Os níveis refletem a amplitude e a profundidade do atendimento dos controles, não apenas o número de controles aprovados.

Veja também: PASS model

Sovereign pillar framework

O 7.º pilar do WAF++, que trata de soberania de dados, conformidade regulatória e controle jurisdicional. Adicionado com 10 controles iniciais (WAF-SOV-010 a WAF-SOV-100). Especialmente relevante para setores regulados e workloads na UE.

T
TSC — Technical Steering Committee governança

O órgão diretivo do projeto WAF++. O TSC é responsável pela direção técnica, pelas decisões sobre RFCs e pela nomeação de mantenedores. Os membros cumprem mandatos renováveis de 12 meses. A composição segue o princípio “contribuidores ativos primeiro” e um equilíbrio neutro entre fornecedores. Todas as decisões do TSC são documentadas publicamente.

Veja também: Governança e comunidade, Papéis e membros

V
Vendor-neutral framework

Um princípio de design central do WAF++: os pilares, os controles e o modelo de pontuação se aplicam igualmente a workloads em qualquer provedor de nuvem (AWS, Azure, GCP e outros). Nenhum controle é específico de um provedor, a menos que esteja explicitamente indicado. Isso permite avaliações consistentes entre provedores e evita o aprisionamento à metodologia de revisão de um único fornecedor.

W
WAF++ framework

Well-Architected Framework Plus Plus. Um framework open source e neutro em relação a fornecedores para avaliar e melhorar a qualidade de workloads em nuvem. O WAF++ amplia as revisões well-architected convencionais com um modelo de pontuação transparente e movido pela comunidade (PASS) e uma biblioteca de controles legível por máquina com 8 pilares e mais de 100 controles.

WAFPass ferramentas

O conjunto oficial de ferramentas de avaliação do WAF++: CLI, servidor, dashboard e scorecard web. O WAFPass consome a biblioteca de controles, avalia um workload e gera um relatório de pontuação PASS. Versão atual: v1.1.0.

Working Group (WG) governança

Uma equipe de contribuidores focada num tema dentro do WAF++. Os grupos de trabalho constroem partes específicas do framework — um pilar, um componente de ferramentas, uma arquitetura de referência — e entregam resultados como PRs e RFCs. Qualquer contribuidor pode propor um grupo com uma carta, uma liderança e um mantenedor patrocinador.

Veja também: Charter, Contribuir

Workload framework

A aplicação, o serviço ou o sistema em nuvem avaliado com o WAF++. Um workload tem um escopo definido (ex.: um microsserviço, uma plataforma de dados, um produto inteiro) e é avaliado com base nos controles aplicáveis do WAF++. O escopo é definido antes de a avaliação começar.

Veja também: Assessment
