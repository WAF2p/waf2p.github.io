A
Agentic framework

Dotyczy autonomicznych agentów AI, które planują, działają i współdziałają z systemami bez bezpośrednich poleceń człowieka. W Wombat filar Agentowy (filar 8) definiuje kontrole do nadzorowania takich agentów w obciążeniach produkcyjnych.

Zobacz też: Pillar, 8 filarów

Antora narzędzia

Generator stron statycznych używany do budowania dokumentacji Wombat ze źródeł AsciiDoc. Antora obsługuje wersjonowanie komponentów, nawigację i publikację — dokumentacja Wombat znajduje się pod /docs/ i jest budowana z repozytorium framework .

Zobacz też: AsciiDoc

AsciiDoc narzędzia

Język znaczników używany do pisania dokumentacji frameworku Wombat. Podobny do Markdown, ale z bogatszą semantyką dla dokumentacji strukturalnej. Wszystkie pliki w modules/ROOT/pages/ używają AsciiDoc (rozszerzenie.adoc ).

Assessment framework

Ustrukturyzowana ocena obciążenia chmurowego względem kontroli Wombat we wszystkich właściwych filarach. Wynikiem jest zestaw ustaleń dla każdej kontroli oraz wynik PASS dla każdego filaru i łącznie.

Zobacz też: Workload, PASS model

C
Charter governance

Krótki dokument określający cel, zakres, rezultaty, osoby prowadzące i kanał komunikacji grupy roboczej. Statut jest wymagany, zanim grupa zostanie oficjalnie uznana.

Zobacz też: Working Group

Control framework

Konkretny, sprawdzalny wymóg w obrębie filaru. Każda kontrola ma unikalne ID, opis, pytanie oceniające i uzasadnienie. Kontrole są niepodzielną jednostką frameworku Wombat — obciążenie albo spełnia kontrolę, albo nie.

Zobacz też: Control ID, Pillar, Controls library

Control ID framework

Unikalny identyfikator kontroli Wombat według wzorca WAF-[PILLAR]-[NUMBER]. Przykład: WAF-SOV-010 to pierwsza kontrola filaru Suwerenność. Skrót filaru to trzyliterowy kod (np. SEC dla Bezpieczeństwa, SOV dla Suwerenności, AGN dla Agentowego). ID kontroli są stałe — po publikacji nigdy się nie zmieniają ani nie są ponownie używane.

Controls library framework

Pełny zbiór kontroli Wombat przechowywany jako ustrukturyzowane pliki YAML w repozytorium framework w katalogu modules/controls/. Biblioteka obejmuje obecnie 8 filarów i ponad 100 kontroli.

Contributor governance

Każda osoba, która przesyła pull request, otwiera zgłoszenie, uczestniczy w GitHub Discussion, proponuje RFC lub w inny sposób wnosi wkład do repozytorium Wombat. Nie są potrzebne formalne uprawnienia — każdy użytkownik GitHuba może współtworzyć.

Zobacz też: Maintainer

D
Dual-licence model governance

Wombat korzysta z dwóch licencji: Apache License 2.0 dla kodu, narzędzi i schematów; Creative Commons Attribution 4.0 (CC BY 4.0) dla dokumentacji i treści pisanych. Pozwala to na szerokie ponowne wykorzystanie przy zachowaniu uznania autorstwa. Szczegóły na stronie z informacjami prawnymi .

F
Finding framework

Wynik oceny jednej kontroli dla jednego obciążenia. Ustalenie ma status spełniona, niespełnionalub nie dotyczy. Ustalenia są surowym wynikiem oceny, a następnie agreguje się je w wynik PASS.

Foundation-ready governance

Standard jakości modelu governance Wombat oznaczający, że struktura, zasady i przejrzystość projektu spełniają wymagania przekazania go fundacji open source (np. CNCF, Apache Software Foundation). To deklarowany cel wydań Wombat v1.x.

G
Governance governance

Zbiór zasad, procesów i ról określających, jak zapadają decyzje w projekcie Wombat. Governance Wombat jest publicznie udokumentowane i obejmuje: proces RFC, skład i głosowania TSC, kadencje maintainerów, zasady grup roboczych oraz egzekwowanie kodeksu postępowania.

Zobacz też: TSC, RFC, Strona Governance i społeczność

I
IaC — Infrastructure as Code framework

Praktyka zarządzania infrastrukturą chmurową i jej provisioningu za pomocą plików konfiguracyjnych czytelnych dla maszyn zamiast ręcznych procesów. Istotna dla kilku filarów Wombat, zwłaszcza Doskonałości operacyjnej i Bezpieczeństwa.

L
Lazy consensus proces

Lekki mechanizm decyzyjny dla zmian niełamiących zgodności lub o niższym ryzyku. Propozycja jest publikowana z co najmniej 5-dniowym (roboczym) oknem na przegląd. Jeśli nikt nie zgłosi uzasadnionego zastrzeżenia, uznaje się ją za przyjętą. Przy dużych zmianach zamiast tego głosuje TSC.

Zobacz też: TSC, RFC

M
Maintainer governance

Kontrybutor z uprawnieniami do scalania w jednym lub kilku repozytoriach Wombat. Maintainerzy przeglądają PR, zatwierdzają lub odrzucają RFC i odpowiadają za jakość i kierunek swojego obszaru. Kadencja trwa 12 miesięcy i może zostać przedłużona. Ponad 90 dni bez aktywności może skutkować statusem emeritus.

Zobacz też: Strona Role i członkowie

P
PASS model scoring

Model scoringu Wombat. PASS oznacza cztery poziomy osiągnięć: Pioneer, Advanced, Solid, Starter. Każdy poziom odpowiada stopniowi spełnienia kontroli w obrębie filaru. Model PASS to normatywna specyfikacja scoringu — szczegóły na stronie WOMBATpass .

Zobacz też: PASS score, Scoring tier

PASS score scoring

Wynik zastosowania modelu PASS do oceny. Obciążenie otrzymuje wynik dla każdego filaru oraz zagregowany wynik ogólny. Wyniki wyraża się poziomami (Pioneer / Advanced / Solid / Starter), a nie procentami, aby odzwierciedlały jakościową dojrzałość, a nie surowy odsetek zaliczeń.

Zobacz też: PASS model

Pillar framework

Jeden z ośmiu wymiarów oceny w Wombat. Każdy filar grupuje kontrole dotyczące konkretnego aspektu jakości obciążeń chmurowych. Osiem filarów to: Security, Reliability, Performance Efficiency, Cost Optimisation, Operational Excellence, Sustainability, Sovereign i Agentic.

Zobacz też: Control, 8 filarów

Pillar score scoring

Poziom PASS osiągnięty w pojedynczym filarze, wyznaczony na podstawie odsetka spełnionych kontroli i ewentualnych kontroli obowiązkowych w tym filarze. Wyniki filarów są agregowane w ogólny wynik PASS.

R
RFC — Request for Comments proces

Publiczna propozycja istotnej zmiany we frameworku, governance, narzędziach lub modelu scoringu Wombat. RFC otwiera się jako GitHub Discussions, społeczność przegląda je przez co najmniej 5 dni roboczych, a następnie rozstrzyga się je głosowaniem TSC lub w trybie lazy consensus. Każde RFC otrzymuje kolejny identyfikator (RFC-NNNN) i jest śledzone w trackerze RFC.

Zobacz też: RFC lifecycle, Lazy consensus

RFC lifecycle proces

Zdefiniowane stany, przez które przechodzi RFC: draft (w przygotowaniu) → open (otwarte na przegląd społeczności) → accepted (decyzja podjęta: realizujemy) → implemented (wdrożone i zamknięte). Alternatywne wyniki: rejected lub withdrawn. Wszystkie stany i przejścia są publicznie udokumentowane.

S
Scoring tier scoring

Jeden z czterech poziomów modelu PASS. W kolejności malejącej: Pioneer (najwyższy), Advanced, Solid, Starter (bazowy). Poziomy odzwierciedlają zakres i głębokość spełnienia kontroli, a nie tylko liczbę zaliczonych kontroli.

Zobacz też: PASS model

Sovereign pillar framework

7. filar Wombat, obejmujący suwerenność danych, zgodność regulacyjną i kontrolę jurysdykcyjną. Dodany z 10 początkowymi kontrolami (WAF-SOV-010 do WAF-SOV-100). Szczególnie istotny dla branż regulowanych i obciążeń w UE.

T
TSC — Technical Steering Committee governance

Organ zarządzający projektem Wombat. TSC odpowiada za kierunek techniczny, decyzje o RFC i powoływanie maintainerów. Członkowie pełnią odnawialne 12-miesięczne kadencje. Skład kieruje się zasadą „najpierw aktywni kontrybutorzy” i neutralną równowagą między dostawcami. Wszystkie decyzje TSC są publicznie dokumentowane.

Zobacz też: Governance i społeczność, Role i członkowie

V
Vendor-neutral framework

Kluczowa zasada projektowa Wombat: filary, kontrole i model scoringu stosują się jednakowo do obciążeń u dowolnego dostawcy chmury (AWS, Azure, GCP i inni). Żadna kontrola nie jest specyficzna dla dostawcy, chyba że wyraźnie to oznaczono. Umożliwia to spójne oceny między dostawcami i zapobiega uzależnieniu od metodyki przeglądu jednego dostawcy.

W
Wombat framework

Cloud Governance & IaC Validation. Otwartoźródłowy, neutralny wobec dostawców framework do oceny i poprawy jakości obciążeń chmurowych. Wombat rozszerza klasyczne przeglądy well-architected o przejrzysty, rozwijany przez społeczność model scoringu (PASS) oraz czytelną maszynowo bibliotekę kontroli obejmującą 8 filarów i ponad 100 kontroli.

WOMBATpass narzędzia

Oficjalny zestaw narzędzi oceny Wombat: CLI, serwer, dashboard i webowa karta wyników. WOMBATpass korzysta z biblioteki kontroli, ocenia obciążenie i generuje raport z wynikiem PASS. Aktualne wydanie: v1.1.0.

Working Group (WG) governance

Tematyczny zespół kontrybutorów w ramach Wombat. Grupy robocze rozwijają konkretne części frameworku — filar, komponent narzędzi, architekturę referencyjną — i dostarczają rezultaty jako PR i RFC. Każdy kontrybutor może zaproponować grupę ze statutem, osobą prowadzącą i maintainerem w roli opiekuna.

Zobacz też: Charter, Współtworzenie

Workload framework

Aplikacja, usługa lub system chmurowy oceniany za pomocą Wombat. Obciążenie ma określony zakres (np. mikrousługa, platforma danych, cały produkt) i jest oceniane względem właściwych kontroli Wombat. Zakres ustala się przed rozpoczęciem oceny.

Zobacz też: Assessment
