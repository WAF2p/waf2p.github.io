Współtworzenie.

Wombat żyje dzięki wkładowi społeczności. Niezależnie od tego, czy piszesz kod, ulepszasz dokumentację, recenzujesz RFC, czy dzielisz się doświadczeniem z prawdziwych projektów — każdy wkład kształtuje framework.

Sposoby współtworzenia.

Kod, treści, społeczność — wybierz to, co pasuje do Twoich umiejętności i czasu.

PR i zgłoszenia

Naprawiaj błędy, implementuj kontrole, ulepszaj narzędzia. Każdy PR jest recenzowany przez maintainera i powiązany z decyzją.

Dokumentacja i wzorce

Pisz dokumentację filarów, architektury referencyjne, wzorce dobrych praktyk lub konkretne przykłady z prawdziwych projektów.

Recenzje RFC

Komentuj otwarte RFC, proponuj alternatywy lub głosuj nad decyzjami dotyczącymi frameworku. Każdy głos się liczy — zwłaszcza perspektywa z praktyki.

Lokalizacja

Pomóż tłumaczyć treści na niemiecki, angielski lub inne języki. Wombat powinien być dostępny dla globalnej społeczności chmurowej.

Grupy robocze

Dołącz do grupy roboczej albo ją zaproponuj — wokół konkretnego filaru, modelu scoringu, biblioteki kontroli lub architektury referencyjnej.

Prelekcje i BoF

Przedstaw Wombat na konferencji, poprowadź sesję Birds-of-a-Feather lub warsztat społeczności. Praktyczne doświadczenie jest bezcenne.

Kto go tworzy.

Prawdziwi ludzie, prawdziwe commity — bez ściany logotypów i zdjęć zespołu z banku zdjęć.

Pierwsze kroki.

Cztery kroki od nowicjusza do kontrybutora.

  1. Poznaj organizację na GitHubie

    Przejrzyj otwarte zgłoszenia z etykietą good first issue lub help wanted na github.com/{{ site.data.github.org }}. Brak odpowiedniego zgłoszenia? Otwórz własne i opisz, czym chcesz się zająć.

  2. Przedstaw się na Slacku

    Dołącz do społeczności na Slacku, przywitaj się na #general, zadawaj pytania i sprawdź, która grupa robocza pasuje do Twojego doświadczenia i zainteresowań.

  3. Fork → gałąź → PR

    Zrób fork odpowiedniego repozytorium, utwórz gałąź funkcjonalności i otwórz pull request. Maintainer go zrecenzuje, przekaże uwagi i przeprowadzi Cię przez proces.

  4. Większe zmiany? Najpierw otwórz RFC

    W przypadku nowych filarów, zmian łamiących zgodność, zmian scoringu lub governance — przygotuj szkic RFC w GitHub Discussions. Społeczność przegląda go przed rozpoczęciem implementacji. Dzięki temu decyzje są identyfikowalne.

Grupy robocze.

Grupy robocze to tematyczne zespoły rozwijające konkretne części Wombat. Każdy może zaproponować grupę — wystarczy statut, co najmniej jedna osoba prowadząca i maintainer w roli opiekuna.

Znajdź grupę

Przejrzyj otwarte propozycje grup w GitHub Discussions i dołącz do odpowiedniego kanału na Slacku. Możesz współtworzyć bez zaangażowania na pełen etat.

Załóż grupę

Przygotuj statut w dyskusji na GitHubie, znajdź maintainera-opiekuna i ogłoś grupę na Slacku. Grupa może mieć dowolny zakres: jeden filar, kwestię narzędzi, podejście do scoringu.

Dostarczaj wyniki

Wyniki grup wracają jako PR i RFC. Każdy wynik jest publiczny, identyfikowalny i możliwy do cytowania — zgodnie z zasadami przejrzystości Wombat.

Cykl życia funkcji.

Każda funkcja Wombat przechodzi przez jasny cykl życia. Każdy etap zależy od procesu RFC/ADR, dzięki czemu użytkownicy zawsze wiedzą, jak dojrzała jest funkcja i czego się spodziewać przed jej wdrożeniem.

Closed Alpha

Prywatne testy

Niewielka grupa early adopterów testuje funkcję w kontrolowanych środowiskach. API, model scoringu lub interfejs CLI są celowo niestabilne i mogą się zmienić bez zapowiedzi.

Jak tu trafia
  • Szkic lub otwarte RFC definiuje eksperyment
  • Grupa wczesnego dostępu tylko na zaproszenie
  • Informacja zwrotna napędza szybkie iteracje
Zobacz szkice RFC →
Alpha

Publiczne testy

Funkcja jest dostępna dla każdego, kto chce ją wypróbować. Interfejsy są w większości stabilne, ale zmiany łamiące zgodność nadal są możliwe na podstawie opinii społeczności.

Jak tu trafia
  • RFC zaakceptowane z zakresem alfa
  • Dostępna publiczna dokumentacja i informacje o wydaniu
  • GitHub Discussions zbiera opinie
Dołącz do dyskusji o wersji alfa →
Beta

Użycie produkcyjne

Funkcja jest kompletna i gotowa do produkcji w udokumentowanych przypadkach użycia. Drobne zmiany są jeszcze możliwe, ale zmiany łamiące zgodność wymagają wyraźnych wskazówek migracji.

Jak tu trafia
  • RFC zaakceptowane, implementacja zmergowana
  • ADR dokumentuje kryteria gotowości produkcyjnej
  • Przegląd bezpieczeństwa, wydajności i zgodności zaliczony
Śledź zaakceptowane RFC →
GA

Ogólna dostępność

Funkcja jest w pełni wspierana, objęta polityką stabilności i zalecana wszystkim użytkownikom. Jest utrzymywana z aktualizacjami zgodnymi wstecz i jasnymi okresami wycofywania.

Jak tu trafia
  • Status RFC zmienia się na implemented
  • Końcowy ADR zatwierdza stabilny kontrakt
  • Dodanie do oficjalnego cyklu wydań
Zobacz wdrożone RFC →

Każdy etap jest powiązany z procesem RFC/ADR. Zaakceptowanie RFC uruchamia etap alfa lub beta; gdy zostanie oznaczone jako implemented , funkcja jest gotowa na GA. Pełny obraz znajdziesz w trackerze RFC albo zaproponuj kolejną zmianę w GitHub Discussions.

Proces RFC.

Istotne zmiany przechodzą przez RFC (Request for Comments). Proces jest lekki, ale gwarantuje, że każda decyzja zostanie przejrzana przez społeczność i udokumentowana.

Żaden wkład nie jest za mały.

Poprawka literówki, wyjaśniający komentarz, recenzja — wszystko posuwa framework naprzód. Wombat powstaje publicznie, a społeczność jest zawsze otwarta.
